## 差异与结论

- **工具序列不同**「豆豆的疫苗本编号是什么？」：手写 [] vs LangGraph ['search_knowledge_base']；两版把选择权都交给模型，差异来自模型采样，不是编排逻辑。
- **答案不同**「豆豆的疫苗本编号是什么？」：手写「我需要查找豆豆的疫苗本编号，但当前没有提供相关背景信息。该信息通常记录在个人健康档案或疫苗接种记录中…」 vs LangGraph「豆豆的疫苗本编号是 **VX-2021-0314-77**。」；同样是模型采样差异。
- **答案不同**「2025 年旅行去了哪些地方？」：手写「根据知识库记录，2025 年旅行去了以下地方： - **4 月**：云南大理，住了 4 晚，入住民宿…」 vs LangGraph「根据知识库中的「六、2025 年旅行记录」部分，已明确记载： - **4 月**：去了**云南大理*…」；同样是模型采样差异。
- **依赖与启动差异**：`agent.py` 不依赖 langgraph；只有选择 `langgraph` 引擎时才延迟导入 `agent_graph.py` 与 langgraph。手写版的启动路径更轻。
- **代码量与抽象**：手写版 538 行（显式 while/for）；LangGraph 版 264 行（StateGraph + 条件边 + 节点）。图版把循环结构声明化，但多了一层框架概念。
- **平均耗时**：手写 4115 ms vs LangGraph 8118 ms；本次差异主要来自模型调用与工具耗时，不能单独归因于框架开销。

## 学习结论

1. **框架替你做了什么**：LangGraph 把"循环 + 条件判断"变成节点与边，状态更新由框架合并；读图就能看懂控制流，但需要理解 State/Node/Edge 这组概念。
2. **框架藏起了什么**：节点的执行顺序、状态合并、递归上限由框架管理；出错时的调用栈更深，排查要先理解框架。
3. **什么时候选手写**：想逐行看懂 loop、依赖越少越好、需要精细控制事件与日志时。
4. **什么时候选 LangGraph**：流程会继续变复杂（分支、并行、人工介入、持久化）时，图的声明式结构更容易扩展。

> 两版被刻意设计为控制流等价；对话层的差异主要来自模型采样。不要为了"看起来不同"而改其中一版的行为。
