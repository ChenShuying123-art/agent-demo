第 1 站 · models.py

真实代码（节选）：

from dataclasses import dataclass
from datetime import datetime
from pathlib import Path


@dataclass
class Document:
    """一篇已上传文档的元数据。"""

    doc_id: str          # 内容 sha256 前 16 位，用于去重
    filename: str
    size: int
    uploaded_at: datetime
    indexed: bool = False
模块（module）工程
一个 .py 文件就是一个模块，文件名去掉 .py 就是模块名。所以 models.py 这个模块就叫 models。
from … import …语法
意思是"从某个模块里，把某个名字拿来用"。from dataclasses import dataclass = 从标准库 dataclasses 里拿 dataclass。不 import 就用不了——这是 Python 里"东西从哪来"的唯一入口。
类型注解 doc_id: str语法
冒号后面是"注解"，告诉人和工具"这个字段应该是字符串"。Python 运行时不会检查它，它更像说明书而不是规则。注意：它不是赋值。
默认值 indexed: bool = False语法
等号后面才是真正的赋值。意思是"创建时如果不给 indexed，就用 False"。
类 class语法
把"一堆数据 + 一堆行为"打包成一个自定义类型。这里的 Document 只装数据，不带行为。
装饰器 @dataclass语法
装饰器 = 贴在类或函数上面、替它"加工"一下的东西。@dataclass 会自动帮你生成 __init__ 等方法，所以你才能写 Document(doc_id="x", size=1)；没有它，你得手写一大堆"把参数存到 self"的代码。（@ 开头的那一行就是装饰器）
docstring语法
写在类/函数第一行的三引号字符串，是它的说明。IDE 悬停提示和 help() 读的就是它。

第 2 站 · config.py

真实代码（节选）：

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        case_sensitive=False,
    )

    dashscope_api_key: str              # 没有默认值
    chat_model: str = "qwen-plus"       # 有默认值
    embedding_dim: int = 1024


settings = Settings()
继承 class Settings(BaseSettings)语法
括号里的是"父类"。写成这样，Settings 就白得了 BaseSettings 的全部能力（自动读环境变量、做类型转换和校验），只需再补充自己的字段。这就是为什么你没写一行"读 .env"的代码，它却会读。
类属性 model_config = …语法
写在类里面、缩进一级的变量，属于"这个类本身"，不是属于某个具体对象。这里它是用来配置 pydantic 的行为（去哪个文件读、大小写敏不敏感）。
环境变量工程
活在操作系统里、程序外面的一组"键 = 值"，程序可以读。为什么不用代码里的常量？因为密钥、地址这类东西会随部署环境变化，而代码不该变。
.env 文件工程
本地开发时，把环境变量按 KEY=VALUE 写进一个文件，省得每次开终端手动设。它绝不能被提交进 git（因为里面有密钥），所以仓库里只放一份 .env.example 当模板。
配置外置工程
"会随环境变化的东西，一律放环境变量，不写进代码"。判断标准很妙：这份代码能不能直接开源，而不泄露任何凭证？ 见 12-Factor App · 配置（中文）。
fail fast：密钥不写默认值工程
dashscope_api_key: str 后面空着，意味着"缺它就直接报错"。宁可启动时立刻崩，也不要带着一个空密钥继续跑，最后在某个深夜炸出一个莫名其妙的 401。
模块级单例 settings = Settings()工程
这一行在文件被 import 时只执行一次，全项目拿到的都是同一个对象。若每个模块各建一个，就会出现"这里读到的模型名和那里不一样"的诡异 bug。
大小写不敏感工程
.env 里写 CHAT_MODEL（惯例大写），会填到 chat_model（Python 惯例小写）。你不用手写转换。

第 3 站 · logging_conf.py

真实代码（节选）：

def setup_logging(level: str | None = None) -> None:
    resolved = (level or settings.log_level).upper()
    logging.basicConfig(
        level=resolved,
        format=_LOG_FORMAT,
        force=True,
    )
函数定义 def 名字(参数):语法
def 是"定义函数"。后面括号里是参数，冒号下面缩进的就是函数体。
联合类型 str | None语法
读作"字符串 或 None"。表示这个参数要么传一个字符串，要么传"什么都没有"。
参数默认值 = None语法
调用时不传这个参数，就自动用 None。所以 setup_logging() 和 setup_logging("DEBUG") 都能调用。
返回类型 -> None语法
箭头后面说明"这个函数返回什么"。None 表示它不返回有意义的值，只是"干活"（这里是把日志配置好）。
关键字参数 force=True语法
按名字传参，而不是按位置。force=True 是传给 basicConfig 的一个开关：强制重建日志配置，保证 Notebook 里格式也统一。
logging工程
标准库，用来输出分级别的信息：DEBUG < INFO < WARNING < ERROR。比 print 强在：能按级别一键过滤、能自带时间和模块名、上线时能整开关掉。
为什么集中配一次工程
如果每个文件都自己配格式，同一份日志会长出五种样子。所以规则是：格式只在一个地方定义，各模块只写 logging.getLogger(__name__) 取自己的 logger。

第 4 站 · __init__.py

真实代码（全部）：

from kbqa.logging_conf import setup_logging

setup_logging()
包（package）工程
一个文件夹 + 里面放一个 __init__.py，Python 就把它当成一个可以 import 的"包"。kbqa/ 就是包。
import kbqa 时发生了什么工程
Python 会执行一次 kbqa/__init__.py 里的代码。所以这行 setup_logging() 会自动跑——只要有人 import 了这个包，日志就统一好了。
为什么只放一行工程
因为 import 包就会连带执行它。入口越轻越好；若在这里 import 一堆业务模块，那么"只想要个配置"的人也会被迫加载全部东西。
回头打通 课程 0001 说"从叶子往根写"，第一片叶子是 models.py。现在你能看懂为什么了：它 import 的全是标准库（dataclasses / datetime / pathlib），一个本项目文件都没有——所以它写完就能立刻单独验证。
