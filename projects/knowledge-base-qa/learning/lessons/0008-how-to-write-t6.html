把外部依赖"包起来"：拆解 T6

T6 的代码很短，但它是本项目第一次出现"抽象"。抽象不是炫技——它解决一个很具体的问题：换模型时，你希望改几个地方？

学完你能做到：看懂"协议 + 工厂"这套结构为什么值得写，并知道怎么把外部 SDK 的异常"翻译"成自己项目能稳定处理的形状。
配套：术语表 · 前置 0002 / 0003

一、两个抽象：协议 + 工厂

T6 只干一件事：把 messages 交给模型，拿回文本。但它包了三样东西：

class LLMProvider(Protocol):          # 只约定"能干什么"
    def chat(self, messages, temperature=None) -> str: ...

class DashScopeChat:                  # 一个具体实现
    def chat(...): ...

def get_llm(settings) -> LLMProvider: # 唯一的创建入口
    return DashScopeChat(settings)
结构作用
Protocol只描述"有哪些方法、什么签名"，不规定怎么实现。业务代码只依赖它
工厂函数集中创建逻辑。要换实现（比如换成别的厂商），只改这一处

好处很实在：以后你想把 qwen-plus 换成别的模型/厂商，只需要新写一个类 + 改工厂一行，pipeline、API、前端全都不用动。这就是 spec NFR-2「可替换」的落地。

回头看你会发现：embeddings.py / rerank.py / llm.py 三个模块长得几乎一样——这不是巧合，是同一套套路重复用。看到"第三次写同样的结构"，就该抽象它了。

二、坑 3：思考模式

这是本任务唯一一个"不看文档必踩"的坑。官方文档写得很直白：

千问 3.8 / 3.7 / 3.6 / 3.5 系列模型默认开启思考模式。建议使用混合思考模型时，显式设置 enable_thinking 参数（true 开启 / false 关闭）。

开启思考模式会发生两件坏事：

  • 更慢更贵：多出一段推理过程要计费
  • 答案可能"不见了"：思考过程放在 reasoning_content 字段，正文放在 content——RAG 场景下你拿到 content 可能是空的

所以代码里必须显式关掉（它不是 OpenAI 标准参数，得走 extra_body）：

extra_body={"enable_thinking": False}

再加一道防御

光传参数还不够——万一哪天换了模型、或配置被人改成 true，你得立刻知道，而不是把空字符串一路传下去变成"模型答不出来"。所以：

if not content:
    logger.error("模型返回空 content（enable_thinking=%s），请检查是否误开了思考模式", ...)
    raise LLMError("模型返回空 content，可能是思考模式未关闭", "empty_content")

空字符串是最危险的返回——它不会报错，只会让上层"以为模型不想回答"。能报错的地方就该报错。

三、给异常"翻译"一层

调用外部服务会失败：key 错、额度用完、地域不对……这些错误由 SDK 抛出来，但SDK 的异常形状不属于你的项目。上层（T10 的 API）需要的是稳定的 {code, message}（§8 要求透传百炼的 code）。

所以在边界上做一次翻译：

try:
    ...
except Exception as exc:
    code = _error_code(exc)                      # 从各种形状里挖出百炼的 code
    raise LLMError(f"LLM 调用失败 code={code}：{exc}", code) from exc

好处：调用方只需要 except LLMError，并且 exc.code 直接可用。实测拿到的错误是 invalid_api_key——这条信息直接告诉你"key 不对"，而不是让你去猜一个 401。

看见最后那个 from exc 了吗？这叫异常链——它保留了原始异常，排查时能看到完整堆栈，不会"翻译"完就丢掉线索。

四、一个容易忽略的细节：temperature 的默认值

spec 的签名写的是 chat(messages, temperature=0.0)。但如果真的写死 0.0，那么 .env 里的 CHAT_TEMPERATURE 就永远不生效——它变成了一个"改了没反应"的摆设。

所以这里改成：

temperature: float | None = None      # None 表示"用配置里的 chat_temperature"

默认行为仍是 0.0（配置默认值就是 0.0，满足 NFR-4 可复现），但配置真的能被配置。

一条通用原则 凡是暴露到 .env 的配置项，都要确认它在代码里真的被读到了。否则它就是在骗未来的你。
