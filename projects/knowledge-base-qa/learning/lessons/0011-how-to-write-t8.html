编排层：把零件装成机器

前面七个任务造了一堆"零件"：切分、向量、入库、重排、提示词、模型调用。T8 第一次把它们装成一台能跑的机器。而编排层最反直觉的一点是——它自己几乎什么都不做。

一、编排层：一个"什么都不做"的模块

看 `RAGPipeline` 的构造函数——它不创建任何东西，只是接住四个已经造好的组件：

def __init__(self, settings, store, embedder, reranker, llm):
    self._store = store
    self._embedder = embedder
    self._reranker = reranker      # 可能是 None
    self._llm = llm

这个手法叫依赖注入：不自己在内部 new 依赖，而是让调用方传进来。

自己 new（耦合写法）注入（本项目写法）
换向量模型改 pipeline 内部代码换传入的 embedder 即可
写测试必须真的调外部接口塞一个假组件就能跑
做消融实验得改代码再改回来换一个参数就行
编排层的三条纪律 它只负责 顺序（先召回再重排）、边界（空输入怎么办、失败怎么降级）、可观测（日志打点）。 它不该自己切分文本、算向量、发请求。一旦它开始"顺手做点事"，前面几个模块的独立性就白做了。

二、为什么把"检索"拆成三段

你完全可以把整个检索写成一个函数：retrieve(question) → 4 条结果。但本项目拆成了三个：

def recall(self, question, doc_ids) -> list[SearchResult]      # 只召回
def rerank(self, question, candidates) -> list[RerankResult]   # 只重排
def retrieve(self, question, doc_ids, use_rerank=None)         # 串起来

理由是 §13 的消融实验（ablation）。消融实验的核心要求是"只改一个变量"——比如"固定提示词，只看重排开/关的影响"。

如果检索只有一个入口，你就没法单独观察"召回给了什么"和"重排把它改成了什么"。拆开之后，实验脚本可以只调用 recall() 看第一阶段，也能对比 retrieve() 开/关重排的差异。

这条思路可以迁移：凡是将来想"单独观察 / 单独开关"的东西，就不要揉成一个函数。

三、`use_rerank`：一个为实验而生的参数

enabled = self._settings.rerank_enabled if use_rerank is None else use_rerank
取值含义用在什么场景
None跟随配置（rerank_enabled）正常问答
True强制开启重排消融实验的"对照组 A"
False强制关闭重排消融实验的"对照组 B"
一个值得学的设计 用 None 表示"跟随配置"，用 True/False 表示"强制"——这样一个参数同时满足"日常默认"和"实验可控"，而且不会因为实验需要而在代码里留下临时开关。

四、降级也要有统一的"形状"

重排不启用、或重排失败时，返回什么？本项目选择：返回和正常重排一样的数据结构，只是把 degraded 标成 True。

@staticmethod
def _degrade(candidates, top_n) -> list[RerankResult]:
    return [
        RerankResult(chunk=item.chunk, rerank_score=item.score,
                     original_rank=item.rank, new_rank=position, degraded=True)
        for position, item in enumerate(candidates[:top_n])
    ]

这样做的价值：上层只需要处理一种形状。如果降级时返回 None、或直接抛异常、或换另一种结构，那前端和 API 层就得写三套分支去应对——分支越多，漏掉一条就是 bug。

六、重排到底值不值？看这份成绩单

本次实测语料是项目自己的 `spec.md` + `tasks.md`（共 172 个 chunk）。问题："Rerank 重排的接口地址是什么？请求体里有哪些字段？"

召回阶段给的前 4 条，和重排之后的前 4 条，差别是这样的：

重排后位置召回时位置变化rerank 分数
new = 0original = 0— 不变0.9677
new = 1original = 11↑ 升 10 位0.9664
new = 2original = 4↑ 升 2 位0.8387
new = 3original = 14↑ 升 11 位0.8181

4 条里有 3 条排名发生了变化，其中两条是从第 12 位、第 15 位一路捞进前 4 的。

再看两组分数，就明白为什么需要重排

阶段分数区间区分度
召回（cosine）0.6508 ~ 0.7256挤在一起——最高和最低只差 0.07
重排（relevance）0.8181 ~ 0.9677拉得开——前二名明显高于后两名
这就是"为什么要两阶段"的实证 召回用的双塔模型区分度有限（分数都挤在 0.65~0.73），它擅长"快速筛掉明显不相关的"，不擅长"精确定序"； 重排用的交叉编码器区分度明显更好。先用便宜的把范围缩小，再用昂贵的把顺序排对——这是整个 RAG 检索的地基。

注意：两组分数不可互相比较（尺度不同），只能各自看排序。这也正是 `RerankResult` 要单独存一个 rerank_score 字段的原因（课程 0007）。
