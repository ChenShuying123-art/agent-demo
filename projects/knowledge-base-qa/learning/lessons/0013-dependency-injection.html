解耦：从协议到依赖注入

课程 0009 讲了"协议"和"工厂"，这一课补上最后一块——依赖注入。三者其实是一条线上的三个环节，服务的都是同一件事：让"变化"只影响一个地方。

学完你能做到：看懂 RAGPipeline 的构造函数为什么长那样；判断哪些东西"该注入"、哪些"不该"；并知道这台"可插拔的机器"是怎么被装配起来的。
配套：术语表 · 前置 课程 0009 / 课程 0011

一、先搞清楚"自己 new"是什么

"new" 是 Java/C++ 的说法。在 Python 里，"自己 new"就是你在代码里亲手写一个构造函数调用、造出一个对象：

self._llm = DashScopeChat(settings)                  # ← 这就是"自己 new"
self._store = VectorStore(settings.data_dir / "index")

那个括号，就是在"造东西"。

所以"不自己在内部 new 依赖"这句话，翻译过来就是：pipeline 内部不要出现 DashScope...(...) 这种调用。

二、两种写法并排看

写法 A：自己 new（耦合写法）

class RAGPipeline:
    def __init__(self, settings):
        self._settings = settings
        self._store = VectorStore(settings.data_dir / "index")         # 自己造
        self._embedder = DashScopeEmbedding(settings)                  # 自己造
        self._reranker = DashScopeRerank(settings) if ... else None     # 自己造
        self._llm = DashScopeChat(settings)                            # 自己造

写法 B：注入（本项目写法）

class RAGPipeline:
    def __init__(self, settings, store, embedder, reranker, llm):
        self._settings = settings
        self._store = store        # 别人造好递给我
        self._embedder = embedder
        self._reranker = reranker
        self._llm = llm
区别只有一句话 谁来决定"用哪个实现"？
写法 A：在 pipeline.py 内部（写死了）。
写法 B：在调用方（外部递进来）。

"依赖注入"这个名字就是这么来的：pipeline 依赖的那几样东西，不是它自己造的，而是被从外部注入进来的。

注意：Python 里它没有任何特殊语法——就是"把参数写进构造函数"。不需要框架、不需要注解。

三、它背后的思想：控制反转

依赖注入不是目的，它服务的是一句话：控制权反转。

谁说了算
以前pipeline 说"我要用百炼"（内部决定）
现在调用方说"我给你用这个"（外部决定）

把"选择权"从内部挪到外部，你就得到了一个可配置、可替换、可测试的组件。

四、三个场景，看差别到底在哪

场景 1：想把向量模型从百炼换成别的

要做什么
写法 A打开 pipeline.py，找到那行 DashScopeEmbedding(settings) 改掉 —— 改动核心文件，可能影响别处
写法 B在 Notebook / API 层把 get_embedding_provider(settings) 换成 本地Embedding() —— pipeline.py 一个字不动

场景 2：想写测试

要做什么
写法 A测试一跑就真的去连百炼 —— 花钱、要联网、慢、网络抖一下测试就红了
写法 B塞一个假 embedder，返回固定向量 —— 0.01 秒跑完、零成本、零网络
 
class 假embedder:
    dim = 1024
    def embed(self, texts): return [[0.1] * 1024 for _ in texts]

pipeline = RAGPipeline(settings, store, 假embedder(), None, 假llm())

这就是课程 0009"练习 A"那个假模型实验真正的用武之地。

场景 3：做消融实验（关掉重排）

要做什么

写法 Bpipeline.retrieve(q, None, use_rerank=False) —— 一个参数

五、本项目的"铁证"

最能说明问题的是 pipeline.py 的 import 那几行：

from kbqa.embeddings import EmbeddingProvider      # ← 接口（协议）
from kbqa.llm import LLMProvider                   # ← 接口（协议）
from kbqa.rerank import RerankProvider             # ← 接口（协议）
看清楚这一点 DashScopeEmbedding、DashScopeChat、DashScopeRerank 这三个具体实现类，pipeline.py 一个都没 import。

也就是说——pipeline 根本不认识"百炼"。它只知道"有个人能满足这个形状"。谁是那个人、从哪来，它不关心、也没法关心。

这就是"解耦"最直白的样子：编排层不认识任何具体实现。

六、一个类比：打印机与墨盒

类比结果
自己 new墨盒焊死在打印机里想换颜色？拆机器。想修？把整台搬走
依赖注入墨盒可插拔想换颜色？拔下来插一个。想试墨盒好不好？拿个假的插上

RAGPipeline 现在就是那台只认"墨盒形状"的打印机——它甚至不知道插进来的到底是不是原厂的。

七、⚠️ 别过度：什么才算"会变"？

"注入会变的东西，不要注入固定的东西"这句话太抽象。先换一个类比。

类比：手机与 SIM 卡 你会换运营商，所以 SIM 卡做成可插拔的；你不会天天换屏幕，所以屏幕焊死在机器里。

所以判断标准不是"它理论上会不会变"，而是——现实中会不会有人真的想把它换掉？

项目里的"SIM 卡"和"屏幕"

东西是什么为什么
embedderSIM 卡 → 注入可能从百炼换成本地模型；测试时要换成假的
llmSIM 卡 → 注入评测时要换模型对比；测试时绝不该真的掏钱调模型
storeSIM 卡 → 注入数据目录可能变；测试想用临时目录
settingsSIM 卡 → 注入换环境（开发 / 生产）就不一样
_CITATION_RE屏幕 → 焊死"引用长什么样"是项目定死的规则，没有第二个版本
logger屏幕 → 焊死日志往哪写由 logging 统一配置，各模块只管拿来用

三个信号：命中一个就值得注入

信号问自己项目的例子
① 有第二个候选"我明天可能换成谁？"embedder：百炼 / 本地模型 / 假的
② 测试要换成假的"跑测试时它还该是真的吗？"llm：测试里不该花钱调真模型
③ 换个环境会变"换台机器、换个环境还一样吗？"store / settings

反过来：三条全不中，就别注入。正则、常量、纯计算——它们没有"另一个版本"，注入只会变成噪音。

过度注入长什么样

如果把"固定的东西"也塞进构造函数，就会变成这样：

class RAGPipeline:
    def __init__(self, settings, store, embedder, reranker, llm,
                 citation_re, logger, json_dumps, perf_counter):   # ← 荒谬
        ...

调用方于是得这么写：

RAGPipeline(..., citation_re=re.compile(r"\[(\d+)\]"),
            logger=logging.getLogger("x"),
            json_dumps=json.dumps,
            perf_counter=time.perf_counter)

这些东西从来不会换。把它们做成参数，唯一的效果是——每个想用 pipeline 的人，都得先搞清楚这 4 个毫不重要的东西该传什么。

一句话 注入"别人可能想换掉的零件"，不要注入"规则和常量"。
口诀：有第二个版本吗？测试要换成假的吗？换个环境会变吗？—— 有一条"是"就注入，全是"否"就写死。

八、三件套怎么配合

把课程 0009 和这一课连起来看，整条装配线是这样的：

① 协议EmbeddingProvider / LLMProvider / RerankProvider
↓ 谁满足这个形状？
② 适配器DashScopeEmbedding
把 SDK 包装成这个形状
替身（测试）假embedder / 假llm
不联网、不花钱
↓ 谁来选？
③ 工厂get_embedding_provider / get_reranker / get_llm
↓ 递给谁？（这就是"注入"）
④ 编排RAGPipeline —— 只认形状，不认实现
图 2 · 协议定形状 → 适配器实现 → 工厂选择 → 注入给编排

看 Notebook 03 里那段装配代码，就是图 2 的文字版：

pipeline = RAGPipeline(
    settings=settings,
    store=store,
    embedder=get_embedding_provider(settings),   # ③ 工厂选 → ④ 注入
    reranker=get_reranker(settings),             # 开了返回实例，关了返回 None
    llm=get_llm(settings),
)
