应用是怎么"装"起来的

你对 api/main.py 的三个疑问，其实指向同一个问题：一个 Web 应用是怎么从"一堆零件"变成"一个能跑的东西"的？这一课就顺着这个文件从头读到尾——为什么要它、最后一行在干嘛、"托管静态资源"又是什么。

学完你能做到：解释 uvicorn api.main:app 里的 app 到底从哪来；看懂 app = create_app() 为什么既是"工厂"又是"单例"；并说清"前端打包产物为什么可以让后端一起发"。
配套：FastAPI 用法手册 · 术语表 · 前置 课程 0014

一、为什么要有 main.py 这个文件

先分清项目里的两类东西：

目录是什么认识 Web 吗
kbqa/能力库：加载、切分、向量、检索、生成……不认识（Notebook 里也能用）
api/把这些能力接到 HTTP 上认识

而 api/main.py 是入口文件（entry point）：FastAPI 必须先有一个"应用对象"才能跑，main.py 就是把零件组装成应用、并把应用暴露出来的地方。

它里面的 create_app() 就是一张"装配清单"，按顺序做五件事：

步代码在干嘛
1VectorStore.load(...)把磁盘上的向量索引加载进内存
2RAGPipeline(store, embedder, ...)把各组件的实现组装成链路（依赖注入）
3app.state.pipeline = pipeline把有状态的对象挂到应用身上，供路由取用
4install_exception_handlers + include_router登记错误处理表和所有路由
5app.mount("/", StaticFiles(...))（可选）顺便托管前端打包产物
一个类比 kbqa/ 是发动机、轮子、方向盘等零件；create_app() 是把它们装成一台车；app = create_app() 是把装好的车摆到车位上、插上钥匙。uvicorn 就是发动它的人。

为什么单独一个文件，而不是塞进 routes.py？因为职责不同：routes 关心"某个 URL 怎么处理"，main 关心"整个应用怎么启动"。入口只有一处，启动相关的事都改这里，排查启动问题时不用到处翻。

二、最后一行 app = create_app() 为什么必须这样写

这一行只有 20 个字符，但要拆成三个问题才讲得清。

2.1 因为 uvicorn 找的是"模块里的一个变量"

启动命令的语法是 模块路径:变量名：

python -m uvicorn api.main:app
#                     └───┬───┘ └┬┘
#                    api/main.py  这个文件里名叫 app 的变量

uvicorn 会：import 这个模块 → 在里面找名叫 app 的变量 → 拿它当应用跑。所以 必须有一个模块级的变量叫 app。这就是最后一行存在的第一个理由。

2.2 为什么是"调用工厂函数"，而不是直接 app = FastAPI()

因为装配步骤有 5 步（见第一节的表）。把这些步骤打包成一个函数有两个好处：

  • 能把它们组织起来、中间还能 return，读起来是"一份清单"而不是散落的语句；
  • 最关键：工厂函数可以被反复调用——测试时 create_app() 能造一个全新的、干净的应用；如果直接 app = FastAPI() 加一堆全局配置，就只有一份，测试之间会互相污染。

2.3 为什么写在"模块最外层"，而且只执行一次

这是本题的核心机制，来自 Python 的 import 规则：

uvicorn 执行 import api.main第一次
↓ Python 从上到下执行这个文件里所有"顶层语句"
执行到 app = create_app()装配发生在这里，只此一次
↓ 执行完，把模块存进 sys.modules 缓存
之后再 import api.main直接取缓存，不再重跑 → app 还是那一个
图 1 · "模块级单例"：import 只执行一次，所以 app 只造一份

换句话说：app = create_app() 既是"调用工厂造对象"，又天然是"全项目唯一一份"——和 T0 里 settings = Settings()、python 里 logging 的模块级对象是同一个套路（术语表叫"模块级单例"）。

2.4 实测证据

import api.main as m1, api.main as m2
print(m1 is m2)          # True   —— 两次 import 是同一个模块对象
print(m1.app is m2.app)  # True   —— 拿到的 app 是同一个
f = m1.create_app()
print(f is not m1.app)   # True   —— 但工厂能再造一个全新的（测试用）

实测的三行输出正是 True / True / True。（顺带能看到日志里"索引已加载"出现了两次：一次是 import 时的 app = create_app()，一次是显式调用的 create_app()——这就是"装配在 import 时真的执行了"的直接证据。）

一个要知道的副作用 app = create_app() 在 import 的那一刻就会真的去加载索引、创建各 provider。这是故意的：配置错了就"启动即报错"（fail fast），而不是等第一个请求进来才发现。 但也要记住：import api.main 是有副作用的，别在无关的地方随手 import 它。
顺带：还有另一种启动写法 uvicorn 也支持"直接指向工厂函数"：uvicorn api.main:create_app --factory。这样就不需要最后那行 app = create_app() 了。 本项目选了"模块级变量 app"，因为它是更通用的写法——部署工具、其他框架大多默认去找一个叫 app 的变量。两种都对，知道有这回事即可。

三、"托管前端静态资源"是什么意思

先把词拆开。静态资源（static assets）= 现成的文件：HTML、CSS、JavaScript、图片、字体。它们的共同点是——每次都一样，不需要后端计算。相对的叫动态接口：同一个 URL，参数不同、或数据变了，返回就不一样（比如 /api/qa 每次问的问题不同，答案就不同）。

3.1 前端怎么变成了"静态文件"

你写的 Vue 源码（.vue + TS）浏览器并不能直接跑，要先"打包"。T11 会用 npm run build 把它编译成 web/dist/ 目录——里面就是 index.html 加一堆 .js / .css。打包之后，前端就退化成了纯粹的静态文件。

3.2 开发模式 vs 生产模式

开发模式生产模式
前端Vite dev server（5173 端口），改代码即时刷新已打包成 web/dist/ 静态文件
后端FastAPI（8000 端口）FastAPI（8000 端口）
怎么联通Vite 的 proxy 把 /api 转给 8000（避免跨域）同一个进程、同一个端口，不存在跨域

问题就在生产模式：那堆静态文件总得有人"发给浏览器"，谁来发？

  • 做法一：另起一个 Nginx 专门发静态文件，API 仍由 FastAPI 管——多一个进程、多一份配置；
  • 做法二（本项目）：让 FastAPI 顺便把 web/dist 也发了。一个进程、一个端口搞定，这就是"托管静态资源"。

3.3 StaticFiles + mount 到底做了什么

app.mount("/", StaticFiles(directory="web/dist", html=True), name="web")
部分含义
StaticFiles(directory="web/dist")把本地目录变成一个"HTTP 文件服务"：请求什么文件，就去这个目录找同名文件返回
html=True访问"目录"时自动返回 index.html（单页应用的入口）
app.mount("/", ...)挂载：在这条 URL 前缀上接一个独立的处理程序，前缀下的请求全归它管

它和路由的区别：路由是"精确匹配某条 URL"，挂载是"一整片 URL 区域都交给它"。mount("/") 的意思是"凡是没有被前面路由接走的请求，都去 web/dist 里找文件"。

浏览器只访问 localhost:8000
↓ 请求先经过已注册的路由
/api/qa→ 路由 → RAGPipeline
其他路径 /、/assets/app.js→ StaticFiles → web/dist 里的文件
图 2 · 一个端口同时服务接口和页面

3.4 为什么外面还套一个 if is_dir()

if _WEB_DIST.is_dir():          # web/dist 存在才挂载
    app.mount("/", StaticFiles(...))

T10 做的时候，T11（前端）还没开始，web/dist 根本不存在。StaticFiles(directory=...) 遇到不存在的目录会启动即报错，所以要先判断。一句话：为将来留好口子，但不能依赖还没发生的事。

3.5 顺序坑（再强调一次）

mount("/") 必须放在 app.include_router(router) 之后。"/" 很贪心，会兜住所有没被匹配的路径；放在前面就会把 /api/health 也当成"去 web/dist 里找 api 文件夹"，全部 404。先具体，后兜底。
