让循环跑起来

T15 有工具表，T16 能读懂 tool_call，T17 有两个真工具。T18 把它们接成一个循环：调模型 → 执行工具 → 回填 → 再调模型，直到模型给答案，或者撞上步数上限。

二、循环骨架：while + for

while rounds < max_steps:
    rounds += 1
    result = llm.chat_with_tools(messages, schemas)

    if not result.tool_calls:          # 模型给答案了
        stop_reason = "final_answer"
        break

    if rounds >= max_steps:            # 最后一轮不再执行工具
        stop_reason = "max_steps"
        break

    messages.append(assistant_message(result))
    for call in result.tool_calls:     # 一轮可能多个工具
        step = run_tool(call)
        steps.append(step)
        messages.append(tool_message(call.id, step.result_text))

三、状态都放在哪里

变量作用
messages完整对话：system → history → user → assistant(tool_calls) → tool…
steps只记工具执行轨迹，供前端与对照实验读取
rounds调了几次模型（不是工具次数）
tool_calls_count实际执行了几次工具（含失败）
last_content最后一次模型文本；max_steps 时可能是唯一能返回的内容
stop_reason为什么停下：final_answer / max_steps
为什么 steps 和 messages 分开 messages 是给模型看的（必须符合 OpenAI 协议）；steps 是给人看的（序号、耗时、成功失败）。 同一份事实，两种视图。前端轨迹面板只读 steps，不需要解析 messages。

四、四条兜底

1. max_steps：循环必须有上限

模型可能一直要求调用工具。AGENT_MAX_STEPS 是刹车：到上限就停，stop_reason="max_steps"，不抛异常。

最后一轮即使模型还在申请工具，也不再执行——执行了也没有下一轮来消费结果。

2. 工具异常：转成文本，继续循环

except Exception as exc:
    ok = False
    text = f"工具执行失败：{exc}"

工具失败不是整个请求失败。把错误摘要回填给模型，它可以换工具、换参数，或者如实告诉用户。

3. 参数不是合法 JSON

模型偶尔会输出坏 JSON。这里不执行 handler，直接记：

arguments = {"_raw": "<模型原文>"}
result_text = "工具参数解析失败：..."

轨迹里保留原文，方便排查"模型到底发了什么"。

4. 重复调用：提醒模型换策略

同一工具 + 同一参数连续出现 ≥ 2 次：

text += "\n\n[提示] 你已连续重复调用同一工具与相同参数，请换一种策略。"

这不会强制中断，而是把"你在原地打转"这个事实告诉模型。真正兜底仍然是 max_steps。

五、截断必须严格

steps[].result_text 的长度必须 ≤ AGENT_TOOL_RESULT_MAX_CHARS。注意省略号也占字符：

text[: limit - 3] + "..."   # 而不是 text[:limit] + "..."

T17 的 kb 工具里也同步修了这个边界——否则刚好卡在上限时会超 3 个字符。
