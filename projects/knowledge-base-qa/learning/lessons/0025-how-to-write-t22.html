课程 0025 · Agent 化实战 · 对应任务 T22

外网工具先跑通链路

T22 是百度搜索工具。真实接口还没定稿、也没有 Key，所以这一课的重点不是"接上百度"，而是把外网工具的正确形状先定下来：可配置 endpoint、10 秒超时、失败返回文本、mock 明确标注、绝不打印 Key。

学完你能做到：说清"mock-first"为什么不是偷懒；写出一个失败不炸链路的外网工具；并知道真实联调状态必须如实记录。
配套：术语表 · 前置 课程 0020

一、工具契约

项约定
名称web_search
参数query 必填；count 1–5，默认 3
返回每条"标题 + URL + 摘要（≤200 字）"，最多 5 条
失败返回错误文本，不抛异常
超时10 秒
配置WEB_SEARCH_ENDPOINT / WEB_SEARCH_API_KEY

二、为什么先 mock

真实接口用哪家、鉴权方式、返回字段都还没定（§19.16）。如果现在硬接一个猜的接口，后面一定返工；更糟的是，把 mock 数据当成联调成功写进报告。

mock-first 的正确姿势 ① 输出里明确写 [mock]；② 日志打 WARNING 并标注"未联调"；③ 报告里写"未联调"，而不是"通过"。
这样链路、参数、错误处理都能先验证，真实接口一到位只替换 HTTP 那一段。

三、可替换的 HTTP 契约

GET {WEB_SEARCH_ENDPOINT}?q=...&count=...
Authorization: Bearer {WEB_SEARCH_API_KEY}

响应（任选其一即可适配）：
{"references": [{"title","url","snippet"}]}
{"results":    [{"title","url","summary"}]}
{"data":       [{"title","link","content"}]}

解析时统一成 title / url / snippet，这样换供应商只改 endpoint 与少量字段映射。

四、失败路径比成功路径更重要

except Exception as exc:
    text = f"web_search 调用失败：{exc}"
    return ToolResult(text=text, data={"query": query, "results": []})

外网一定会抖。工具层把异常转成文本，agent loop 就能把它当作一次普通工具结果继续；如果直接抛，虽然 loop 也会兜住，但错误信息不如这里可读。

五、Key 安全

  • Key 只从 .env 读，不写进代码；
  • 日志只打 query / count / 来源 / 成功率 / 耗时，绝不打 Key；
  • 错误文本里也不拼 Key（异常信息通常只有 URL 与状态码）。

附：代码全流程拆解

T22 的流程：收敛参数 → 判断 mock/real → 发请求 → 统一字段 → 截断 → 返回 ToolResult。真实接口未定稿，所以 endpoint 与响应字段都做成可替换的。

阶段代码产出
① 参数query / _parse_countquery + count（1–5）
② 分支endpoint/key 是否为空mock 或 real
③ 请求httpx.get(..., timeout=10)JSON
④ 解析_parse_responsetitle / url / snippet
⑤ 格式化_format_results编号文本
⑥ 返回ToolResulttext + data

1. 工厂 + handler 骨架

def build_web_search_tool(settings: Settings) -> Tool:
    @tool(name="web_search", description="...", parameters={...})
    def web_search(args: dict) -> ToolResult:
        query = str(args.get("query") or "").strip()
        count = _parse_count(args.get("count"))

        if not query:
            return ToolResult(text="搜索词不能为空。")

        endpoint = settings.web_search_endpoint.strip()
        api_key = settings.web_search_api_key.strip()
        if not endpoint or not api_key:
            results = _mock_results(query, count)
            return ToolResult(text=_format_results(results), data={...})
        ...

为什么用工厂：endpoint/key 来自 Settings，不能在模块导入时写死；工厂把配置注入，测试时可以传假 endpoint。

2. 真实请求：超时 + Bearer

resp = httpx.get(
    endpoint,
    params={"q": query, "count": count},
    headers={"Authorization": f"Bearer {api_key}"},
    timeout=_TIMEOUT_SECONDS,
)
resp.raise_for_status()
results = _parse_response(resp.json(), count)

超时固定 10 秒；外网失败统一捕获成文本，不让异常穿透到 agent loop。

3. 解析：兼容三种响应形状

items = payload.get("references") or payload.get("results") or payload.get("data") or []
for item in items[:count]:
    results.append({
        "title": str(item.get("title") or ""),
        "url": str(item.get("url") or item.get("link") or ""),
        "snippet": _clip(str(item.get("snippet") or item.get("summary") or ""), 200),
    })

换供应商时只改字段映射；工具对外的 title/url/snippet 结构保持不变。

4. 格式化：模型能直接读

[1] 标题
URL: https://...
摘要: ...

[2] 标题
URL: https://...
摘要: ...

最多 5 条，每条摘要 ≤200 字；返回前再交给 agent loop 的总长度截断兜底。

5. 失败路径

情况行为
query 为空"搜索词不能为空"
未配置 endpoint/keymock 结果，带 [mock]，日志 WARNING
超时 / 非 2xx"web_search 调用失败：..."，不抛异常
返回空列表"web_search 未检索到结果"

七、亲手做一遍

练习 A · 换一种响应形状 把 _parse_response 改成适配 {"data":[{"link","content"}]}，用本地 mock 服务器返回，确认字段映射生效。
练习 B · 制造超时 把 endpoint 指向一个不响应的地址，确认 10 秒后返回错误文本而不是卡死。
