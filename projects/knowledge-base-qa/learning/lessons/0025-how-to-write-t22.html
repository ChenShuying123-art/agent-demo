课程 0025 · Agent 化实战 · 对应任务 T22

外网工具先跑通链路

T22 是百度搜索工具。真实接口还没定稿、也没有 Key，所以这一课的重点不是"接上百度"，而是把外网工具的正确形状先定下来：可配置 endpoint、10 秒超时、失败返回文本、mock 明确标注、绝不打印 Key。

学完你能做到：说清"mock-first"为什么不是偷懒；写出一个失败不炸链路的外网工具；并知道真实联调状态必须如实记录。
配套：术语表 · 前置 课程 0020

一、工具契约

项约定
名称web_search
参数query 必填；count 1–5，默认 3
返回每条"标题 + URL + 摘要（≤200 字）"，最多 5 条
失败返回错误文本，不抛异常
超时10 秒
配置WEB_SEARCH_ENDPOINT / WEB_SEARCH_API_KEY

二、为什么先 mock

真实接口用哪家、鉴权方式、返回字段都还没定（§19.16）。如果现在硬接一个猜的接口，后面一定返工；更糟的是，把 mock 数据当成联调成功写进报告。

mock-first 的正确姿势 ① 输出里明确写 [mock]；② 日志打 WARNING 并标注"未联调"；③ 报告里写"未联调"，而不是"通过"。
这样链路、参数、错误处理都能先验证，真实接口一到位只替换 HTTP 那一段。

三、可替换的 HTTP 契约

GET {WEB_SEARCH_ENDPOINT}?q=...&count=...
Authorization: Bearer {WEB_SEARCH_API_KEY}

响应（任选其一即可适配）：
{"references": [{"title","url","snippet"}]}
{"results":    [{"title","url","summary"}]}
{"data":       [{"title","link","content"}]}

解析时统一成 title / url / snippet，这样换供应商只改 endpoint 与少量字段映射。

四、失败路径比成功路径更重要

except Exception as exc:
    text = f"web_search 调用失败：{exc}"
    return ToolResult(text=text, data={"query": query, "results": []})

外网一定会抖。工具层把异常转成文本，agent loop 就能把它当作一次普通工具结果继续；如果直接抛，虽然 loop 也会兜住，但错误信息不如这里可读。

五、Key 安全

  • Key 只从 .env 读，不写进代码；
  • 日志只打 query / count / 来源 / 成功率 / 耗时，绝不打 Key；
  • 错误文本里也不拼 Key（异常信息通常只有 URL 与状态码）。

六、实测数据

验收点实测
mock 搜索 3 条✅ 每条含标题 / URL / 摘要，带 [mock]，结果 514 字
错误 endpoint✅ 返回「web_search 调用失败：…」，不抛异常（2750ms）
Key 是否进日志✅ 日志无 Key（仅 query / count / 来源 / 结果长度 / 耗时）
真实联调⚠️ 未联调（无 Key / endpoint），mock 结果已明确标注

七、亲手做一遍

练习 A · 换一种响应形状 把 _parse_response 改成适配 {"data":[{"link","content"}]}，用本地 mock 服务器返回，确认字段映射生效。
练习 B · 制造超时 把 endpoint 指向一个不响应的地址，确认 10 秒后返回错误文本而不是卡死。
练习 C · 检查日志脱敏 故意把 Key 设成一个显眼字符串，跑一次失败路径，搜索日志确认它没有出现。
