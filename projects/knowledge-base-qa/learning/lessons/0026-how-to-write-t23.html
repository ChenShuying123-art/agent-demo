课程 0026 · Agent 化实战 · 对应任务 T23

城市名不是经纬度

T23 是天气工具。它和 T22 共享同一套外网工具骨架，但有一个关键设计：参数用城市名，不用经纬度。因为模型更会给"北京"，而不是"39.9, 116.4"。

学完你能做到：理解工具参数要"顺着模型的表达习惯"；处理"城市不存在"这类业务错误；并复用 mock-first + 超时 + 错误文本的三件套。
配套：术语表 · 前置 课程 0025

一、工具契约

项约定
名称get_weather
参数city 必填（城市名）；days 1–7，默认 1
返回城市 / 日期 / 天气 / 温度
失败城市不存在或外网失败 → 返回错误文本，不抛异常
超时10 秒
配置WEATHER_ENDPOINT / WEATHER_API_KEY

二、为什么参数是城市名

模型对"北京"的把握，远高于"39.9042, 116.4074"。工具参数应该顺着模型的表达习惯设计，而不是顺着后端 API 的习惯。

设计原则 参数面向模型，不面向数据库。如果后端需要经纬度，就在工具内部把城市名转成坐标（或交给天气 API 自己转），不要让模型承担这个转换。

三、mock 模式如何模拟"城市不存在"

_MOCK_CITIES = {"北京": ("晴", "18~25°C"), "上海": (...), ...}

if city not in _MOCK_CITIES:
    return ToolResult(text=f"未找到城市：{city} 的天气信息。")

mock 只认识一个小城市表，其它城市按"不存在"处理。这样错误路径也能被验收，而不是永远返回一段假天气。

四、输出格式

城市：北京（mock）

日期：2026-10-18
天气：晴
温度：18~25°C

三个字段分行，模型能直接引用。`days > 1` 时按天重复"日期/天气/温度"块。

附：代码全流程拆解

T23 的流程与 T22 同构：收敛参数 → mock/real 分支 → 取数据 → 统一字段 → 格式化。差异点是业务校验：城市不存在要给出明确错误。

阶段代码产出
① 参数city / _parse_dayscity + days（1–7）
② 分支endpoint/key 是否为空mock 或 real
③ 取数_mock_forecast 或 httpx.get每日天气列表
④ 校验城市是否认识 / 返回是否为空错误文本或数据
⑤ 格式化_format城市 / 日期 / 天气 / 温度
⑥ 返回ToolResulttext + data

1. 工厂 + handler 骨架

def build_weather_tool(settings: Settings) -> Tool:
    @tool(name="get_weather", description="...", parameters={...})
    def get_weather(args: dict) -> ToolResult:
        city = str(args.get("city") or "").strip()
        days = _parse_days(args.get("days"))

        if not city:
            return ToolResult(text="城市不能为空。")

        endpoint = settings.weather_endpoint.strip()
        api_key = settings.weather_api_key.strip()
        if not endpoint or not api_key:
            if city not in _MOCK_CITIES:
                return ToolResult(text=f"未找到城市：{city} 的天气信息。")
            forecast = _mock_forecast(city, days)
            return ToolResult(text=_format(city, forecast, "mock"), data={...})
        ...

mock 也做业务校验：只认识小城市表，其它城市按"不存在"处理。否则错误路径永远测不到。

2. mock 预报：确定性数据

def _mock_forecast(city: str, days: int) -> list[dict]:
    weather, temp = _MOCK_CITIES[city]
    today = date.today()
    return [
        {
            "date": (today + timedelta(days=offset)).isoformat(),
            "weather": weather,
            "temp": temp,
        }
        for offset in range(days)
    ]

mock 用当前日期生成，保证"今天/明天"的日期是连续的；输出里明确标注 （mock）。

3. 真实请求与解析

resp = httpx.get(
    endpoint,
    params={"city": city, "days": days},
    headers={"Authorization": f"Bearer {api_key}"},
    timeout=_TIMEOUT_SECONDS,
)
resp.raise_for_status()
forecast = _parse_response(resp.json(), days)
items = payload.get("days") or payload.get("forecast") or payload.get("data") or []
for item in items[:days]:
    forecast.append({
        "date": str(item.get("date") or item.get("day") or ""),
        "weather": str(item.get("weather") or item.get("text") or ""),
        "temp": str(item.get("temp") or item.get("temperature") or ""),
    })

与 T22 一样，字段映射集中在 _parse_response；换供应商不改 handler。

4. 输出：按天分块

城市：北京（mock）

日期：2026-10-18
天气：晴
温度：18~25°C

days > 1 时重复"日期/天气/温度"块；模型可以直接引用其中某一天。

5. 失败路径

情况行为
city 为空"城市不能为空"
mock 中不存在的城市"未找到城市：..."
真实接口无数据"未找到城市：..."
超时 / 非 2xx"get_weather 调用失败：..."，不抛异常
