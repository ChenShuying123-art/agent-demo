工具跑在另一个进程里

T24 写一个 MCP server，只暴露一个工具：write_markdown。重点不是"能写文件"，而是写文件的边界：目录固定、拒绝路径穿越、内容有上限。MCP 让工具跑在独立进程里，安全边界也更容易划清。

学完你能做到：理解 MCP 的 server / client / stdio 三个词；用官方 SDK 注册一个工具；并把"模型无权指定路径"写成代码而不是口号。
配套：术语表 · 前置 课程 0020

一、MCP 是什么（一句话版）

agent（client）本进程
↔ stdio（JSON-RPC）
md_writer（server）另一个 python 进程
图 1 · 工具不在你的进程里，通过协议调用

本项目用 stdio：不需要网络，本机就能跑，而且能直观看到"工具跑在另一个进程里"。

二、用官方 SDK 注册工具

from mcp.server.mcpserver import MCPServer

server = MCPServer("md_writer")

@server.tool(name="write_markdown", description="...")
def write_markdown(filename: str, content: str) -> str:
    ...

if __name__ == "__main__":
    server.run()   # 默认 stdio

本项目使用 mcp 2.x；1.x 里这个类叫 FastMCP，2.x 改名为 MCPServer（API 基本一致）。

注意：函数签名就是 schema 的来源（filename: str / content: str），这与本地工具的"手写 JSON Schema"不同——MCP SDK 替你生成了 schema。

三、写盘边界（本课重点）

candidate = Path(name)
if candidate.is_absolute() or candidate.name != name or ".." in candidate.parts:
    return "写入失败：filename 只能是纯文件名，不能包含路径或 ..。"
  • 目录固定：EXPORT_DIR 由服务端决定，模型只能给文件名；
  • 拒绝绝对路径 / 盘符：C:\evil.md、/etc/passwd 都不行；
  • 拒绝 ..：../../evil.md 会被 candidate.name != name 拦住；
  • 双保险：写入前再 resolve().relative_to(EXPORT_DIR) 校验一次；
  • 内容上限：超过 200,000 字符直接拒绝，避免一次写爆磁盘。
为什么不用"清洗文件名" 把 ../../evil.md 洗成 evil.md 看似友好，但会让调用方以为自己成功了。这里的工具选择了更明确的行为：拒绝并说明原因，模型下一轮可以改成合法文件名。
