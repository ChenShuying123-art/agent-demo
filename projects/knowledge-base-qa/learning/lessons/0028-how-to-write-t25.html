把远程工具接进同一张表

T24 的 server 只会在另一个进程里说话。T25 写 client：启动时 tools/list，把每个远程工具包装成本地 Tool，注册进同一个 registry。这样 agent loop 完全不知道"这个工具在另一个进程里"。

学完你能做到：说清 MCP client 的三步（list → wrap → register）；理解名称前缀与失败隔离；并知道"默认关闭 + 延迟 import"为什么重要。
配套：术语表 · 前置 课程 0027

一、三步接入

① tools/list启动 server，拿回工具清单
↓
② 包装成 Toolname = server.tool，parameters = inputSchema
↓
③ registry.register与本地工具同表，loop 无感知
图 1 · 远程与本地在 registry 这一层被抹平

二、名称前缀：避免撞名

full_name = f"{server_name}.{remote_name}"
# 例：md_writer.write_markdown

没有前缀，两个 server 都暴露 write_markdown 时就会撞名。前缀也是模型看到的工具名——它仍然能理解。

三、失败隔离

try:
    remote_tools = _list_tools_sync(settings, spec)
except Exception as exc:
    logger.warning("MCP server 启动失败 name=%s 原因=%s", server_name, exc)
    continue

某个 server 命令写错、崩溃、超时，只丢这一批工具；本地工具与 /api/agent/chat 仍然可用。MCP 不是必需依赖。

四、默认关闭 + 延迟 import

if not settings.mcp_enabled:
    logger.info("MCP 未启用，跳过")
    return
# 真正要用时才：
from mcp import ClientSession

这样即使环境里没装 mcp，MCP_ENABLED=false 的应用也能正常启动。实测：关闭时 "mcp" not in sys.modules。

五、每次调用开一个会话：一个明确的取舍

当前实现每次 tools/call 都重新启动 server、握手、调用、关闭。好处是隔离好、实现简单；代价是每次多几秒（实测 3–5 秒）。

什么时候该改成常驻会话 当工具调用频率变高、延迟不可接受时，再引入"后台事件循环 + 长连接"。本批优先可观测性与实现简单，先不做连接池。
