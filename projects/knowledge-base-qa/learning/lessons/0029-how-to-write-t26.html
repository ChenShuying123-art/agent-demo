课程 0029 · Agent 化实战 · 对应任务 T26

给 agent 一本工作手册

skill = 一段提示词正文 + 一组允许使用的工具。它不是新能力，而是把"某类任务该怎么做"写成可加载的手册。T26 要落地两件事：用户显式指定，以及模型经 load_skill 自动选择。

学完你能做到：理解渐进披露（先给目录、再给正文）；说清"收窄工具集"如何防止越权；并知道显式与自动两条触发路径分别怎么走。
配套：术语表 · 前置 课程 0021

一、一个 SKILL.md 长什么样

---
name: daily-brief
description: 当用户想了解"今天该知道什么"时使用：日期 + 天气 + 知识库里的相关约定
tools: [get_datetime, get_weather, search_knowledge_base]
---

回答流程：
1. 先用 get_datetime 获取日期与星期。
2. 如果用户提到城市，用 get_weather 查询。
3. 再用 search_knowledge_base 查相关记录。
……

front-matter 只有三个字段：name / description / tools。正文只写"做什么、怎么回答"，不放代码。

二、渐进披露：先目录，后正文

启动只读 name + description → 注入 system
↓ 模型判断需要
load_skill(name)正文进 system，工具集收窄
↓
后续轮次只看到该 skill 的工具
图 1 · 正文按需加载，避免一开始就塞满上下文

三、两条触发路径

路径怎么走工具集
显式请求里 skill="daily-brief"启动即收窄
自动模型调用 load_skill加载后收窄

SKILL_AUTO_SELECT=false 时只保留显式路径：不注入 skill 清单，也不提供 load_skill。

四、收窄工具集：不是"多给"，而是"少给"

allowed_tools = set(skill.tools) if skill.tools else None

def _filter_schemas(base, allowed, load_skill_available):
    schemas = [s for s in base if allowed is None or s["function"]["name"] in allowed]
    if load_skill_available:
        schemas.append(LOAD_SKILL_SCHEMA)
    return schemas

加载 kb-research 后，模型只看到 search_knowledge_base，看不到日期、天气、网页搜索、MCP 写文件。这是权限收窄，不只是提示词建议。

为什么不用 if-else 判断 skill skill 的价值在于"一组工具 + 一段提示词"的组合。用数据结构表达（tools 列表），代码只需要过滤 schema，不需要为每个 skill 写分支。

五、解析 front-matter 为什么不用 PyYAML

格式很简单（三行 key: value），自己解析就够，避免为一个 demo 引入新依赖。代价是只支持扁平结构；如果以后要嵌套字段，再换 YAML。

附：代码全流程拆解

T26 的流程分两条：显式指定在 loop 开始前就注入正文并收窄工具；自动选择先给目录，模型调 load_skill 后再注入并收窄。

阶段显式自动
① 解析_resolve_skill(name)无，先列清单
② system注入正文注入 name + description 清单
③ 工具集allowed_tools = skill.tools全量 + load_skill
④ 加载—模型调用 load_skill
⑤ 收窄启动即生效加载后对后续轮次生效

1. 解析 SKILL.md：front-matter + 正文

parts = text.split("---", 2)
meta = {}
for line in parts[1].splitlines():
    if ":" in line:
        key, value = line.split(":", 1)
        meta[key.strip().lower()] = value.strip()

name = meta.get("name") or path.parent.name
description = meta.get("description", "").strip()
body = parts[2].strip()
tools = _parse_tools(meta.get("tools", ""))

只支持扁平字段（name / description / tools），所以不引入 PyYAML；tools 支持 [a, b] 或逗号分隔。

2. 显式指定：启动即收窄

active_skill = self._resolve_skill(skill)   # 不存在 -> ValueError
auto_skills = self._auto_skills(active_skill)

messages = _build_initial_messages(
    question, history, self._system_prompt(active_skill, auto_skills)
)
allowed_tools = set(active_skill.tools) if active_skill and active_skill.tools else None

_system_prompt 把正文追加到 system；allowed_tools 为 None 表示继承全部，否则只保留 skill 声明的工具。

3. 自动模式：先给目录 + load_skill

load_skill_available = bool(auto_skills) and active_skill is None
schemas = _filter_schemas(base_schemas, allowed_tools, load_skill_available)

def _filter_schemas(base, allowed, load_skill_available):
    schemas = [s for s in base
               if allowed is None or s["function"]["name"] in allowed]
    if load_skill_available:
        schemas.append(LOAD_SKILL_SCHEMA)
    return schemas

模型看到 skill 清单后，自己决定是否调用 load_skill；load_skill 不是 registry 里的普通工具，而是 loop 特殊处理。

4. 加载：正文进 system，工具收窄

if call.name == LOAD_SKILL_NAME:
    step, loaded, last_signature, repeat_count = self._run_load_skill(...)
    steps.append(step)
    messages.append({"role": "tool", "tool_call_id": call.id,
                     "content": step.result_text})
    if loaded is not None:
        active_skill = loaded
        allowed_tools = set(loaded.tools) if loaded.tools else None
        load_skill_available = False
        messages[0]["content"] = self._system_prompt(active_skill, [])

三个动作缺一不可：① 回填 tool 消息；② 更新 system prompt；③ 收窄后续轮次的工具集。只做 ①，模型看得到正文但权限没变；只做 ③，模型不知道为什么要换工具。

5. 失败路径

情况行为
SKILL.md 缺 front-matter加载期 WARNING，跳过该 skill
name 重复WARNING，跳过后一个
显式 skill 不存在ValueError → API 400 skill_not_found
load_skill 名字不存在ok=False 的 step，loop 继续
tools 里有未注册工具不会凭空出现：_filter_schemas 只从已注册工具里选
