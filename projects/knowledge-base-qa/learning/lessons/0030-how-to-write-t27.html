让回答一点点出现

普通 HTTP 要等整次 agent 跑完才返回；SSE 可以在过程里持续推事件。T27 用一条 text/event-stream 连接把 step_start / tool_call / tool_result / token / done 逐个发给前端。

学完你能做到：说清 SSE 与普通 JSON 响应的区别；理解"后台线程 + 队列 → 生成器"的桥接方式；并知道本课的 token 流是"答案分片"，不是模型原生 token 流。
配套：术语表 · 前置 课程 0021

一、事件格式

event: tool_result
data: {"event":"tool_result","index":0,"tool":"get_datetime","ok":true,...}

event: token
data: {"event":"token","text":"今天是 **20"}

每条事件两行：event: 类型 + data: JSON，块之间空一行。前端按 \n\n 切块即可。

二、后端：线程 + 队列 + 生成器

worker 线程runner.run(on_event=queue.put)
↓
queue.Queue事件缓冲
↓
StreamingResponse逐个 yield "event/data"
图 1 · 同步 loop 不改，外面包一层异步输出

为什么不直接做成 async：`AgentRunner.run` 是同步的（工具也是同步的）。用一个后台线程跑它，主线程只负责把队列里的事件写出去，改动最小。

三、token 事件的真相

诚实说明 本课的 token 是把最终答案按 8 字分片发出，用于前端逐字渲染；模型本身仍是一次性返回。真正的原生 token 流需要改 LLM 层（stream=True + 解析 delta），不在本批范围。报告与课程里都要写清楚这一点。

四、前端：ReadableStream 解析

const reader = resp.body.getReader()
const decoder = new TextDecoder()
let buffer = ''
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  const blocks = buffer.split('\n\n')
  buffer = blocks.pop() ?? ''
  for (const block of blocks) {
    const line = block.split('\n').find(l => l.startsWith('data: '))
    if (line) onEvent(JSON.parse(line.slice(6)))
  }
}

两个易错点：① 必须保留最后一段不完整的 buffer；② 解码用 { stream: true }，否则中文跨块会乱码。

五、前端如何增量渲染

  • tool_result → push 进 steps，轨迹列表立刻出现；
  • token → answer += text，文字逐渐出现；
  • done → 用最终值覆盖（包含 skill / stop_reason / 耗时）。

注意直接把对象赋给 ref 后，要通过 agentResult.value（响应式代理）修改字段；改原始对象不会触发重渲染。

附：代码全流程拆解

T27 的流程：HTTP 请求 → 后台线程跑 loop → 事件进队列 → 生成器写 SSE → 前端逐块解析 → 增量渲染。同步 loop 不改，只在外面包一层流式输出。

阶段代码产出
① 接请求agent_chat_streamquestion / skill
② 后台跑threading.Thread(worker)事件写入 queue.Queue
③ 事件runner.run(on_event=events.put)step_start / tool_call / tool_result
④ 分片最终答案按 8 字切token 事件
⑤ 输出StreamingResponse(generator)event: ... / data: ...
⑥ 前端agentChatStream追加 answer / steps

1. 后端：worker + queue + generator

events: queue.Queue = queue.Queue()

def worker():
    run = runner.run(payload.question, payload.skill, payload.history,
                     on_event=events.put)
    for offset in range(0, len(run.answer), 8):
        events.put({"event": "token", "text": run.answer[offset:offset+8]})
        time.sleep(0.02)
    events.put({"event": "done", "answer": run.answer, ...})
    events.put(None)

threading.Thread(target=worker, daemon=True).start()

def generator():
    while True:
        item = events.get()
        if item is None:
            break
        yield f"event: {item['event']}\ndata: {json.dumps(item, ensure_ascii=False)}\n\n"

return StreamingResponse(generator(), media_type="text/event-stream")

为什么用线程：AgentRunner.run 和工具都是同步的；后台线程跑它，主线程只把队列事件写出去，改动最小。

2. 事件从哪来：AgentRunner 的 on_event

while rounds < max_steps:
    rounds += 1
    _emit(on_event, {"event": "step_start", "round": rounds})
    result = self._llm.chat_with_tools(messages, schemas)

    for call in result.tool_calls:
        _emit(on_event, {"event": "tool_call", "index": len(steps),
                         "tool": call.name, "arguments": call.arguments})
        step = self._run_tool(...)
        _emit(on_event, _step_event(step))

_emit 内部吞掉回调异常：前端断开时，不能让 agent 主循环崩掉。

4. 增量渲染：先空结果，再按事件填

agentResult.value = { answer: '', skill: payload.skill, steps: [], ... }
const current = agentResult.value as AgentRun

await api.agentChatStream(question, skill, (ev) => {
  if (ev.event === 'step_start') current.rounds = ev.round
  else if (ev.event === 'tool_result') current.steps.push({ ... })
  else if (ev.event === 'token') current.answer += ev.text
  else if (ev.event === 'done') { current.answer = ev.answer; ... }
})

必须改 agentResult.value（Vue 的响应式代理），不要改赋值的原始对象；否则界面不会更新。

5. 失败路径

情况行为
模型/工具异常worker 发 error 事件，然后结束
客户端断开daemon 线程继续跑完；回调异常被 _emit 吞掉
非 2xx前端解析错误信封，抛 ApiError
中文跨块TextDecoder(..., {stream:true}) 保证不乱码

边界：token 是答案分片，不是模型原生 token 流；真正的原生流需要改 LLM 层的 stream=True 解析。
