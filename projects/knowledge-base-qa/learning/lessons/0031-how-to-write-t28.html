一、图长什么样

llm 节点调模型，产出 pending_calls
↓ 条件边
tools 节点执行工具，回填 messages
↺ 回到 llm
END模型不再请求工具 / 达到上限
图 1 · 和 while 循环是同一件事，只是换了表达方式

二、四个核心概念

概念在本项目里
StateAgentState：messages / steps / rounds / pending_calls / active_skill…
Nodellm_node（调模型）、tools_node（执行工具）
Edgetools → llm；llm → tools 或 END（条件边）
recursion_limit图的执行上限，作为 max_steps 之外的保险

三、关键设计：继承手写版

class GraphAgentRunner(AgentRunner):
    def run(...):
        active_skill = self._resolve_skill(skill)
        ...
        final = graph.invoke(initial, config={"recursion_limit": max_steps * 2 + 4})

继承不是为了复用循环，而是复用循环之外的一切：skill 解析、工具执行、截断、重复检测、日志。这样两版的差异只剩图本身。

四、条件边怎么写

def route(state):
    return "tools" if state["pending_calls"] else "end"

graph.add_conditional_edges("llm", route, {"tools": "tools", "end": END})
graph.add_edge("tools", "llm")

llm_node 里如果模型不再请求工具，就把 pending_calls 置空并设置 stop_reason；条件边看到空列表就走向 END。
