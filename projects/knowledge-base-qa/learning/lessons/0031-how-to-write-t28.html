T18 用 while 写了 loop。T28 用 LangGraph 再写一遍：工具、skill、AgentRun 全部复用，只把"循环"换成状态图。这样对比才公平——差异只能来自编排方式。

配套：术语表 · 前置 课程 0021

一、图长什么样

llm 节点调模型，产出 pending_calls
↓ 条件边
tools 节点执行工具，回填 messages
↺ 回到 llm
END模型不再请求工具 / 达到上限
图 1 · 和 while 循环是同一件事，只是换了表达方式

二、四个核心概念

概念在本项目里
StateAgentState：messages / steps / rounds / pending_calls / active_skill…
Nodellm_node（调模型）、tools_node（执行工具）
Edgetools → llm；llm → tools 或 END（条件边）
recursion_limit图的执行上限，作为 max_steps 之外的保险

三、关键设计：继承手写版

class GraphAgentRunner(AgentRunner):
    def run(...):
        active_skill = self._resolve_skill(skill)
        ...
        final = graph.invoke(initial, config={"recursion_limit": max_steps * 2 + 4})

继承不是为了复用循环，而是复用循环之外的一切：skill 解析、工具执行、截断、重复检测、日志。这样两版的差异只剩图本身。

四、条件边怎么写

def route(state):
    return "tools" if state["pending_calls"] else "end"

graph.add_conditional_edges("llm", route, {"tools": "tools", "end": END})
graph.add_edge("tools", "llm")

llm_node 里如果模型不再请求工具，就把 pending_calls 置空并设置 stop_reason；条件边看到空列表就走向 END。

五、延迟导入

if engine == "langgraph":
    from kbqa.agent_graph import GraphAgentRunner

AGENT_ENGINE=handwritten 时进程内不会加载 langgraph——实测 "langgraph" not in sys.modules。可选依赖不能变成必需依赖。

附：代码全流程拆解

T28 的流程：工厂选引擎 → 初始化 State → graph.invoke → llm 节点 → 条件边 → tools 节点 → 回到 llm → END → 映射成 AgentRun。

阶段代码产出
① 选引擎create_agent_runnerAgentRunner 或 GraphAgentRunner
② 初始状态AgentStatemessages / steps / rounds / pending_calls
③ 图执行graph.invoke(initial)最终 state
④ 映射AgentRun(...)与手写版同契约

1. 工厂：延迟导入，按配置选

def create_agent_runner(settings, registry, llm, skills=None):
    engine = (settings.agent_engine or "handwritten").strip().lower()
    if engine == "handwritten":
        return AgentRunner(settings, registry, llm, skills)
    if engine == "langgraph":
        from kbqa.agent_graph import GraphAgentRunner
        return GraphAgentRunner(settings, registry, llm, skills)
    raise ValueError(f"未知的 AGENT_ENGINE：{settings.agent_engine!r}")

handwritten 模式不会 import langgraph；可选依赖不能变成必需依赖。

2. 初始状态：一张共享的 state

initial: AgentState = {
    "messages": messages,
    "steps": [],
    "rounds": 0,
    "tool_calls_count": 0,
    "last_content": None,
    "stop_reason": "max_steps",
    "active_skill": active_skill,
    "allowed_tools": allowed_tools,
    "load_skill_available": load_skill_available,
    "last_signature": None,
    "repeat_count": 0,
    "pending_calls": [],
}
final = graph.invoke(initial, config={"recursion_limit": max_steps * 2 + 4})

recursion_limit 是图的保险丝；max_steps 仍是业务上限，两者都要有。

3. llm 节点：调模型，决定下一步

def llm_node(state):
    rounds = state["rounds"] + 1
    schemas = _filter_schemas(base_schemas, state["allowed_tools"],
                              state["load_skill_available"])
    result = self._llm.chat_with_tools(state["messages"], schemas)

    if not result.tool_calls:
        return {"rounds": rounds, "last_content": result.content,
                "pending_calls": [], "stop_reason": "final_answer"}

    if rounds >= max_steps:
        return {"rounds": rounds, "last_content": result.content,
                "pending_calls": [], "stop_reason": "max_steps"}

    messages = list(state["messages"]) + [_assistant_message(result)]
    return {"rounds": rounds, "last_content": result.content,
            "messages": messages, "pending_calls": result.tool_calls}

节点返回的是状态增量，不是最终 AgentRun；图结束后再统一映射。

4. 条件边：pending_calls 决定去向

def route(state):
    return "tools" if state["pending_calls"] else "end"

graph.add_conditional_edges("llm", route, {"tools": "tools", "end": END})
graph.add_edge("tools", "llm")

这条边就是 while 循环的"下一轮"；没有它，图跑完一轮就结束。

5. tools 节点：与手写版共用执行逻辑

def tools_node(state):
    for call in state["pending_calls"]:
        if call.name == LOAD_SKILL_NAME:
            step, loaded, ... = self._run_load_skill(...)
            if loaded:
                messages[0] = {"role": "system",
                               "content": self._system_prompt(loaded, [])}
        else:
            step, ... = self._run_tool(...)
        steps.append(step)
        messages.append({"role": "tool", "tool_call_id": call.id,
                         "content": step.result_text})

    return {"messages": messages, "steps": steps, "pending_calls": []}

_run_tool 与 _run_load_skill 直接继承手写版，所以截断、异常、重复检测两版完全一致。

6. 一次执行的完整流程

  1. create_agent_runner 选到 GraphAgentRunner；
  2. 构造 initial state；
  3. graph.invoke 进入 llm 节点；
  4. 有 tool_calls → 条件边去 tools；
  5. tools 执行、回填、清空 pending_calls；
  6. 回到 llm；无 tool_calls 或达到上限 → END；
  7. 把最终 state 映射成 AgentRun。
