课程 0034 · 接口层 · api/schemas.py 的职责边界

一次请求的完整旅程

你已经知道 schemas.py 的定位是"只定义对外数据结构与转换函数"。这一课把这句话放回一次真实请求里：JSON 进来 → 请求模型 → 路由 → agent → 内部 DTO → 转换函数 → response_model → JSON 出去。顺带回答一个容易含糊的问题：response_model 到底自动做了什么、没做什么。

学完你能做到：指着任意一个接口，说出五个站点各自负责什么；判断一件事该手写转换函数，还是交给 FastAPI；知道响应校验失败时会变成什么错误。
配套：FastAPI 用法手册 · 课程 0014 · FastAPI 接口层

一、全景：一次请求经过五个站点

以 POST /api/agent/chat 为例：

浏览器
  │  {"question": "今天几号？"}
  ▼
① 请求模型      AgentChatRequest         JSON → Python 对象
  ▼
② 路由          agent_chat()             取参数、调 agent
  ▼
③ 业务          AgentRunner.run()        question/skill/history → AgentRun
  ▼
④ 转换          to_agent_run_out()       AgentRun → AgentRunOut
  ▼
⑤ 响应模型      response_model=AgentRunOut  校验 + 序列化
  ▼
浏览器
     {"answer": "...", "steps": [...], ...}
站点代码位置输入 → 输出一句话职责
① 请求模型api/schemas.py:57JSON → AgentChatRequest进门验票
② 路由api/routes.py:221请求对象 → 调用业务HTTP 语义
③ 业务kbqa/agent.py:61普通参数 → AgentRun真正干活
④ 转换api/schemas.py:252AgentRun → AgentRunOut内部语言翻译成对外语言
⑤ 响应模型路由装饰器AgentRunOut → JSON出门打包

二、第 1 站：请求模型负责"进门验票"

客户端发来的最小请求：

POST /api/agent/chat
Content-Type: application/json

{"question": "今天几号，星期几？"}

对应的模型在 api/schemas.py:57：

class AgentChatRequest(BaseModel):
    question: str
    skill: str | None = Field(default=None, description="指定 skill；缺省为自动选择")
    history: list[dict] = Field(default_factory=list, description="可选的历史消息")

FastAPI 在调用路由函数之前就完成了校验和默认值填充，得到：

AgentChatRequest(
    question="今天几号，星期几？",
    skill=None,
    history=[],
)
这里只做形状检查，不做业务判断 question 缺失或不是字符串 → 422 validation_error。
但"问题问得好不好""skill 存不存在"都不归它管——后者要等第 3 站才知道。

三、第 2 站：路由只做 HTTP 语义

api/routes.py:221 的实际代码：

@router.post("/agent/chat", response_model=AgentRunOut)
def agent_chat(payload: AgentChatRequest, request: Request) -> AgentRunOut:
    try:
        run = _agent(request).run(payload.question, payload.skill, payload.history)
    except ValueError as exc:
        if payload.skill is not None:
            raise ApiError(400, "skill_not_found", f"skill 不存在：{payload.skill}") from exc
        raise
    return to_agent_run_out(run)

注意它没有把整个 payload 传下去，而是拆成三个普通参数：

run = _agent(request).run(
    payload.question,   # str
    payload.skill,      # str | None
    payload.history,    # list[dict]
)

这样 kbqa/ 完全不需要 import FastAPI 或 Pydantic。删掉整个 api/，核心库照样能被 Notebook 调用——这正是"接口层是翻译官，不是干活的人"的判断标准。

四、第 3 站：业务层返回内部 DTO

AgentRunner.run() 执行完工具循环后，构造的是内部 AgentRun（kbqa/models.py:104）：

AgentRun(
    answer="今天是2026年10月19日，星期一。",
    skill=None,
    steps=[
        AgentStep(
            index=0,
            tool="get_datetime",
            arguments={"date": "today"},
            result_text="2026-10-19 星期一 08:30:00 今天（+0 天）",
            ok=True,
            elapsed_ms=8,
        )
    ],
    stop_reason="final_answer",
    tool_calls_count=1,
    rounds=2,
    latency_ms=2035,
)

它是 @dataclass，属于内部契约。内部对象可以持有 Path、datetime 这类 Python 类型，不需要考虑"JSON 能不能表示"。

五、第 4 站：转换函数把内部语言翻译成对外语言

api/schemas.py:252：

def to_agent_run_out(run: AgentRun) -> AgentRunOut:
    return AgentRunOut(
        answer=run.answer,
        skill=run.skill,
        steps=[
            AgentStepOut(
                index=step.index,
                tool=step.tool,
                arguments=step.arguments,
                result_text=step.result_text,
                ok=step.ok,
                elapsed_ms=step.elapsed_ms,
            )
            for step in run.steps
        ],
        stop_reason=run.stop_reason,
        tool_calls_count=run.tool_calls_count,
        rounds=run.rounds,
        latency_ms=run.latency_ms,
    )

它做的是：

AgentRun        →  AgentRunOut
AgentStep       →  AgentStepOut
内部 dataclass  →  对外 Pydantic 模型

没有业务计算，只是逐字段搬运和类型转换。这样内部结构改动时，不会悄悄改变对外 API 的形状。

六、第 5 站：response_model 自动做了什么

触发点就是路由装饰器上的这一句：

@router.post("/agent/chat", response_model=AgentRunOut)

自动发生的三件事

路由函数 return 一个值
      ↓
FastAPI serialize_response()
      ↓
① Pydantic 按 response_model 校验
      ↓
② jsonable_encoder 转成可 JSON 化的 dict
      ↓
③ 包成 JSONResponse 输出
  • 校验：返回值必须符合 AgentRunOut 声明的形状；
  • 过滤：只保留模型里声明过的字段，多余字段会被丢掉；
  • 序列化：datetime → ISO 字符串，None → null，嵌套模型递归处理。

同时，/docs 里这个接口的响应示例，也来自 response_model。

一个容易误解的细节

本项目的转换函数已经返回了 AgentRunOut 实例。Pydantic v2 的 revalidate_instances 默认是 "never"，所以同类型模型实例通常会被直接放行，不会逐字段重跑一遍校验。

换句话说，这里的"再校验一次"更像兜底 + 统一出口：正常路径上它几乎不做事，但一旦有人返回了错误形状，它能立刻发现。

哪些自动、哪些不自动

事情谁来做
按模型校验响应字段✅ FastAPI 自动
丢弃模型未声明的字段✅ FastAPI 自动
datetime / None 的 JSON 序列化✅ FastAPI 自动
生成 /docs 的响应 schema✅ FastAPI 自动
AgentRun → AgentRunOut 的字段对应❌ 手写 to_agent_run_out()
elapsed_ms → ms 这类改名❌ 手写转换
Path → str 这类类型转换❌ 手写转换
HTTP 状态码与错误信封❌ routes.py
一句话分工 "翻译"是手写的（to_xxx_out）；"校验 + 序列化 + 输出 JSON"是 FastAPI 自动的。

如果响应校验失败会怎样

FastAPI 会抛 ResponseValidationError。当前 routes.py 没有专门处理它，因此会落到最后的兜底处理器：

{
  "error": {
    "code": "internal_error",
    "message": "..."
  }
}

HTTP 状态码是 500。因为这时属于"服务端返回了不符合契约的数据"，不是用户请求错误——用户没有做错什么。

如果去掉 response_model

FastAPI 仍会用 jsonable_encoder 序列化，但：

  • 不再按模型校验；
  • 不再过滤多余字段；
  • /docs 里没有明确的响应结构。

所以 response_model 既是校验开关，也是 API 契约的声明。

七、为什么不能直接把 AgentRun 返回给前端

看一个更直白的例子。索引接口内部拿到的是：

{
    "doc_id": "abc123",
    "chunks": 12,
    "elapsed_ms": 87,
}

但对外的字段规定叫 ms。路由在 api/routes.py:154 做了显式转换：

IndexItemOut(
    doc_id=item["doc_id"],
    chunks=item["chunks"],
    ms=item["elapsed_ms"],
)

如果直接把内部 dict 返回，外部字段就会变成 elapsed_ms，API 契约被内部实现"泄露"。

同理：Document.path 内部是 Path，对外必须是字符串，所以 to_document_out() 会主动执行 str(doc.path)。

八、错误链路也走同一个边界

如果请求是：

{"question": "今天几号？", "skill": "not-exist"}

第 1 站的形状校验能通过；第 3 站发现 skill 不存在，抛 ValueError；第 2 站把它翻译成：

raise ApiError(400, "skill_not_found", f"skill 不存在：{payload.skill}")

全局处理器最终返回：

HTTP/1.1 400 Bad Request

{
  "error": {
    "code": "skill_not_found",
    "message": "skill 不存在：not-exist"
  }
}
出错位置HTTP 状态code
请求体形状不对422validation_error
用户输入的业务值不对400invalid_request / skill_not_found
上游模型调用失败502透传百炼的 code
响应形状不符合契约500internal_error

错误信封由 routes.py 的 _error_json() 统一构造；schemas.py 里的 ErrorResponse 只用于文档展示。

十、带走这张清单

写一个新接口时，按顺序问五句 ① 外部 JSON 长什么样？→ 建 XxxRequest
② 路由需要从里面取哪几个值？→ 拆成普通参数传给业务层
③ 业务层返回的内部 DTO 是什么？→ @dataclass
④ 内部字段要怎么翻译成对外字段？→ 写 to_xxx_out()
⑤ 对外响应的形状是什么？→ 声明 response_model
五句都能答上来，这个接口的边界就清楚了。
