FastAPI 用法手册

这份手册只讲一件事：FastAPI 怎么写。所有例子都来自本项目的 api/ 三个文件（main.py / routes.py / schemas.py），看的时候开着它们对照，边读边点 /docs 看效果。

学完你能做到：独立写出一个"能解析参数、能校验、能返回固定结构、出错有统一格式、还自带文档页"的小接口。不需要背 API，记住"这块语法解决什么问题、去哪个文件里找例子"就够了。
配套：课程 0014 · 术语表 · FastAPI 官方教程（中文）

零、FastAPI 到底替你做了什么

不用框架时，你要自己写：解析 URL、读 JSON、校验字段、拼 HTTP 状态码、把对象转 JSON……这些"重复的脏活"FastAPI 全包了，你只要写普通的 Python 函数。具体是四件事：

它做的你只要写本项目在哪看到
把 URL 映射到函数（路由）贴一个装饰器@router.get("/health")
解析并校验参数写类型注解 + pydantic 模型qa(payload: QARequest)
对象 ⇄ JSON 自动转换直接 return 对象return to_document_out(doc)
生成接口文档页什么都不用做启动后访问 /docs

心法：你写 Python，它管 HTTP。凡是在写"怎么解析请求/怎么拼响应"的代码，多半是没用好框架。

一、最小可运行应用

一个能跑的 FastAPI 应用，最短只要三行：

from fastapi import FastAPI

app = FastAPI()                    # 1. 造一个"应用"对象

@app.get("/hello")                 # 2. 把下面的函数"挂"到 GET /hello 上
def hello():
    return {"msg": "hi"}           # 3. 返回 dict，框架自动转成 JSON

再配一条启动命令（main 是文件名，app 是里面那个变量名）：

python -m uvicorn main:app --reload
#               └──┬──┘ └┬┘  └── 改了代码自动重启（开发时用）
#              文件名.py  变量名

访问 http://127.0.0.1:8000/hello 就能看到 {"msg":"hi"}。

对照本项目：为什么是 app = create_app() api/main.py 最后一行是 app = create_app()，而不是直接 app = FastAPI()。 多包一层函数，是为了在造应用的同时把依赖装好（加载向量库、组装 pipeline、挂异常处理、注册路由）。 uvicorn 找的是变量 app——只要是 FastAPI 实例就行，怎么来的它不管。

二、路由：APIRouter 与装饰器

小项目可以直接 @app.get(...)。但路由一多，全堆在一个文件里会很乱，于是用 APIRouter 把一组路由打包，最后再合并进 app：

# api/routes.py —— 定义一组路由
router = APIRouter(prefix="/api", tags=["kbqa"])   # 统一前缀 /api，文档里归为一组

@router.get("/health", response_model=HealthResponse)
def health(request: Request) -> HealthResponse: ...

@router.post("/documents", response_model=DocumentOut)
async def upload_document(request: Request, file: UploadFile = File(...)): ...

@router.delete("/documents/{doc_id}", response_model=DeleteResponse)
def delete_document(doc_id: str, request: Request): ...
# api/main.py —— 把整组路由合并进来
app.include_router(router)

三件事要分清：

  • 装饰器（@router.get(...)）：把函数登记进"URL → 函数"的对照表。它长得像课程 0001 里的 @dataclass，都是"替你加工"。
  • 方法名（get / post / delete）：对应 HTTP 方法，同一个路径可以用不同方法挂不同函数。
  • prefix：给这一组路由统一加前缀。所以 @router.get("/health") 真正的地址是 /api/health。

三、参数从哪来（最该记住的一张表）

FastAPI 靠函数参数判断"这个值要从请求的哪儿取"。规则如下，建议背下来：

参数写法框架去哪取本项目例子
名字和路径里的 {} 一致路径参数def delete_document(doc_id: str, ...) ← /{doc_id}
类型是 BaseModel 的子类请求体（JSON）payload: QARequest
file: UploadFile = File(...)上传的文件（multipart）upload_document
类型是 Request整个请求对象（要啥自己取）request: Request
普通标量、且不在路径里查询参数（?x=1）本项目未用

这张表是本手册的核心。看懂它，你就能看懂任何 FastAPI 路由的签名——每个参数都能在大脑里还原成"它是从请求的哪里来的"。

路径参数：名字必须和 {} 一模一样

@router.delete("/documents/{doc_id}")
def delete_document(doc_id: str, request: Request) -> DeleteResponse:
    docs = {d.doc_id: d for d in loaders.list_documents(...)}
    doc = docs.get(doc_id)                 # ← 直接用，框架已经帮你取好并转成 str
    if doc is None:
        raise ApiError(404, "document_not_found", f"文档不存在：{doc_id}")

类型注解 str 不是装饰：写 doc_id: int，框架会自动把 URL 里的 "123" 转成数字 123；转不动就返回 422。Request 类型的参数不参与"取参"，它只是让你能拿到请求对象本身（见第七节）。

四、请求体与校验：pydantic BaseModel

POST 的 JSON body，用一个继承 BaseModel 的类来描述：

# api/schemas.py
from pydantic import BaseModel, Field

class QARequest(BaseModel):
    question: str
    style: str | None = None          # 可省略 → 默认 None
    doc_ids: list[str] | None = None
    use_rerank: bool | None = None

class IndexRequest(BaseModel):
    doc_ids: list[str] = Field(min_length=1)   # 额外约束：至少要有一个元素

写完之后，校验是免费的——框架在调用你的函数之前先对照这个类检查：

客户端发来的结果
{}（漏了必填的 question）422，函数体根本不执行
{"doc_ids": []}422（违反 min_length=1）
{"question": "..."}通过，拿到 payload.question
关键：校验发生在函数被调用之前 这是你第一次能看到"框架夹在中间"的地方。类型注解在这里从"给人和工具看的注释"变成了真正会执行的检查——这也是课程 0001 里说"注解运行时不被强制"的一个例外：框架主动读了它。

五、响应：response_model 与返回值

给路由加 response_model=...，相当于声明"这个接口保证吐出长这样的 JSON"：

@router.get("/documents", response_model=list[DocumentOut])
def list_documents(request: Request) -> list[DocumentOut]:
    return [to_document_out(doc) for doc in loaders.list_documents(...)]

它的作用有两个：

  • 序列化：返回值只保留模型里声明过的字段，并转成 JSON（datetime → ISO 字符串、Path 早已在转换函数里变成 str）；
  • 文档：/docs 上这个接口的"响应示例"就来自它。
为什么本项目不直接 return 内部的 dataclass 内部 Document 有 path: Path（JSON 里没有"路径对象"），字段名也可能和对外约定不同（pipeline 用 elapsed_ms，对外要 ms）。所以先用 to_xxx_out() 把内部对象翻译成对外模型，再返回。
规矩：返回值必须是 response_model 声明的那种模型实例（或它能校验通过的东西）。类型对不上，FastAPI 会在返回时报错——这其实是在帮你抓 bug。

状态码默认 200。想改成别的（例如新建返回 201）可以写 @router.post("/documents", status_code=201)。本项目没改，因为"上传命中去重"时返回的是已有记录，201 反而会误导。

六、async def 还是 def？（本项目的选择）

FastAPI 两种都支持，但行为不同：

写法框架怎么跑适合
def（普通函数）丢进线程池跑，不卡住主循环同步的耗时操作，如调 pipeline
async def直接在事件循环里跑需要 await 的异步操作，如读上传文件
 
# api/routes.py —— 需要 await 读文件，所以是 async
@router.post("/documents", response_model=DocumentOut)
async def upload_document(request: Request, file: UploadFile = File(...)) -> DocumentOut:
    content = await file.read()      # ← 只有 async 函数里才能 await
    doc = loaders.save_upload(file.filename or "unnamed.txt", content, ...)
    return to_document_out(doc)

# 其余路由都是普通 def —— 它们内部是同步调用（pipeline 会真的去调模型）
@router.post("/qa", response_model=QAResultOut)
def qa(payload: QARequest, request: Request) -> QAResultOut:
    ...
一句话原则 不要在 async def 里做同步的慢操作（比如直接 requests.get 或调模型），那会把整个事件循环堵死，其他请求全部排队。 本项目除了"上传读文件"必须 async，其余一律用普通 def——让框架把它们丢进线程池，反而更安全。

七、拿共享对象：Request 与 app.state

路由有时候需要"应用启动时就造好的东西"，比如 pipeline。做法是：启动时挂到 app.state，请求时通过 request.app.state 取。

# api/main.py —— 装配时挂上去（只做一次）
app.state.settings = settings
app.state.store = store
app.state.pipeline = pipeline

# api/routes.py —— 请求时取出来用
def _pipeline(request: Request) -> RAGPipeline:
    return request.app.state.pipeline

@router.post("/qa", response_model=QAResultOut)
def qa(payload: QARequest, request: Request) -> QAResultOut:
    result = _pipeline(request).answer(payload.question, style, payload.doc_ids, ...)
    return to_qa_out(result)
顺带认识一下 Depends（本项目没用，但你会到处看到） FastAPI 官方还有一套依赖注入语法 Depends，写法是 def qa(pipeline: RAGPipeline = Depends(get_pipeline))，靠框架自动注入。 本项目选了更直白的 request.app.state：一个 _pipeline(request) 助手函数，读起来没有"魔法"，也不需要额外记一套机制。 两种都对；看懂别人的代码时知道 Depends 是干嘛的就行。

八、报错：三种写法，本项目选了哪一种

写法怎么用特点
直接 return JSONResponse(...)自己拼响应灵活，但会绕过 response_model，错误形状容易散落各处
抛 HTTPException(404, "…")FastAPI 自带简单；但它默认返回 {"detail": ...}，形状不统一
自定义异常 + @app.exception_handler本项目做法路由只管"抛"，形状统一由一处翻译
 
# 1) 定义自己的异常（routes.py）
class ApiError(Exception):
    def __init__(self, status_code: int, code: str, message: str): ...

# 2) 路由里直接抛
raise ApiError(404, "document_not_found", f"文档不存在：{doc_id}")

# 3) 集中注册处理器，翻译成统一信封
@app.exception_handler(ApiError)
async def _handle_api_error(request: Request, exc: ApiError):
    return JSONResponse(status_code=exc.status_code,
                        content={"error": {"code": exc.code, "message": exc.message}})

加了处理器之后，任何没被单独处理的异常也能兜住，保证前端永远拿到同一个形状：

抛出的异常最终响应
ValueError400 {"error":{"code":"invalid_request",...}}
ApiError(404, ...)404 {"error":{"code":"document_not_found",...}}
请求体校验失败422 {"error":{"code":"validation_error",...}}
上游模型报错502，code 用百炼原始的（如 invalid_api_key）

处理器写在 install_exception_handlers(app) 里，由 create_app() 调用一次。错误约定只写一次——这就是"统一信封"的实现方式。

这块想细看 → 专门一课 "异常是什么、为什么自定义、@app.exception_handler 怎么接住它"，已单独讲透： 课程 0015 · 自定义异常与异常处理器。

九、上传文件：UploadFile

from fastapi import File, UploadFile

@router.post("/documents", response_model=DocumentOut)
async def upload_document(request: Request, file: UploadFile = File(...)):
    content = await file.read()            # 读成 bytes
    doc = loaders.save_upload(file.filename or "unnamed.txt", content, settings.data_dir)
    return to_document_out(doc)
  • File(...) 里的 ... 读作"必填"。写成 File(None) 就变成可选。
  • file.filename 是客户端传来的原始文件名——属于外部输入，不可信（课程 0003 的路径穿越讲的就是它）。
  • 依赖 python-multipart：处理 multipart 表单需要它，否则启动报错。已在 requirements.txt 里。

十、白拿的文档页：/docs

启动后打开 http://127.0.0.1:8000/docs，你会看到一个可交互的接口列表——它是根据你的路由、类型注解、pydantic 模型自动生成的，一行额外代码都不用写。

地址内容
/docs可点的接口文档（Swagger UI），能直接 "Try it out" 调接口
/openapi.json机器可读的接口描述，/docs 就是用它渲染的
/redoc另一种风格的文档页

所以"路由数量对不对"有个极快的检查法：数 /openapi.json 里的 paths。文档即契约——你写的类型注解有多准，文档就有多准。

十一、托管静态文件：StaticFiles 与挂载顺序

把前端构建产物（web/dist）交给 FastAPI 一起托管：

from fastapi.staticfiles import StaticFiles
from pathlib import Path

_WEB_DIST = Path("web") / "dist"

app.include_router(router)                 # ← 先注册 /api/* 路由
if _WEB_DIST.is_dir():                     # ← 目录不存在就跳过（前端还没构建时不报错）
    app.mount("/", StaticFiles(directory=_WEB_DIST, html=True), name="web")
  • html=True：访问目录时自动返回 index.html，适合单页应用。
  • 顺序是坑：mount("/") 会兜住所有没被前面匹配的路径。若放在 include_router 之前，/api/health 会被当成"静态目录里找 api 文件夹"→ 404。先具体、后兜底。

十二、本地测接口：TestClient

不想开浏览器时，可以用 TestClient 在 Python 里模拟请求（本项目自测就用它）：

from fastapi.testclient import TestClient
from api.main import app

client = TestClient(app)
r = client.get("/api/health")
print(r.status_code, r.json())      # 200 {'status': 'ok', ...}

r = client.post("/api/index", json={"doc_ids": ["deadbeef"]})
print(r.status_code, r.json())      # 400 {'error': {'code': 'invalid_request', ...}}

r = client.post("/api/documents", files={"file": ("a.md", b"hello", "text/markdown")})
print(r.status_code)                # 上传用 files= 而不是 json=

它底层真的会走一遍路由（校验、异常处理、序列化都生效），只是不经过网络。写完接口先写几行 TestClient 把错误路径跑绿，再连真实服务。

十三、常见坑清单（都来自本项目注释）

  • 启动命令写错：是 模块路径:变量名（api.main:app），不是文件路径。
  • 路径参数名字对不上：/{doc_id} 配 def f(doc_id)，错一个字母就变成"普通查询参数"或直接报错。
  • 返回类型与 response_model 不符：返回了 dataclass/dict 却不是声明的模型，框架会报校验错。
  • 异步里做同步慢操作：在 async def 里调阻塞接口，会拖垮整个服务。
  • mount("/") 放错位置：抢走 API 路由，全部 404。
  • 忘了 python-multipart：一用 UploadFile 就启动失败。
  • 把业务塞进路由：路由应该只有"解析 → 委托 → 翻译"，否则 Notebook 和 API 会各持一份逻辑。
