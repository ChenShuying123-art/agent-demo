T0 骨架速查卡

压成一页的要点。写新模块时照着走；忘了为什么，回 课程 0001。

四步法

步做什么判断标准
1规格变成清单，不写代码字段名 / 类型 / 默认值都列全了
2从最底层文件开始写排在第一的那个，import 了 0 个项目内文件
3一个文件 + 一行命令验证出错时只有一处可能是元凶
4整体连起来跑最终验收失败必在"集成"层，不在细节

T0 的四个文件

顺序文件职责依赖
1models.py@dataclass 数据结构无
2config.py.env → Settings 对象pydantic-settings
3logging_conf.py日志格式与级别config
4__init__.py只调用一次 setup_logging()logging_conf

三个"为什么"（最容易被问到）

  • 密钥不给默认值 → fail fast：缺配置就启动即崩，别带着错配置跑。
  • settings 只实例化一次 → 全项目共用一份配置，避免配置漂移。
  • 日志只在一处配置 → 各模块只 getLogger(__name__)，格式才统一。

验收命令

python -c "import kbqa; print('ok')"
python -c "from kbqa.config import settings; print(settings.chat_model, settings.embedding_dim, settings.rerank_model, settings.log_level)"
python -c "import logging, kbqa; logging.getLogger('kbqa').info('test')"
$env:LOG_LEVEL='DEBUG'; python -c "import logging, kbqa; logging.getLogger('kbqa').debug('x')"

没有 .env 时先设 $env:DASHSCOPE_API_KEY='sk-test'。

踩坑提醒

  • 别从 __init__.py 开写——它会调用还不存在的东西，你会卡死在第一步。
  • 别把四个文件全写完再一起测——报错时你无法定位是哪一步。
  • .env 必须在 .gitignore 里；仓库只留 .env.example。
