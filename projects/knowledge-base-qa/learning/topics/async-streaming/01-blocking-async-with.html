专题 · 01

同步、阻塞与 async with

先把三个常被混用的词拆开：同步 / 异步、阻塞 / 非阻塞、上下文管理器。搞清这三个，async with 就只剩一层语法糖。

一、两个轴，不是一件事

同步异步
调用方式直接调用，返回即结果await / Future / 回调
等待时线程被占用，不能干别的可以让出，去处理别的任务
本项目例子AgentRunner.run()stdio_client / ClientSession

另一个轴是“阻塞”与“非阻塞”，说的是等待时怎么返回：

  • 阻塞：等到有结果才返回（网络、磁盘、time.sleep、子进程）。
  • 非阻塞：立刻返回“还没好”，稍后再问。

最常见的组合是同步 + 阻塞，本项目就是；asyncio 是异步 + 非阻塞。

关键区分 阻塞 ≠ 吃满 CPU。等待网络时 CPU 占用可能是 0%，但线程仍然被占着，不能执行别的代码。

二、阻塞到底发生在哪一行

沿着流式路由的调用链往下看：

routes.py:243   def agent_chat_stream(...)              # 同步函数
  └─ agent.py:61   def run(...)                          # 同步函数
       └─ agent.py:123  self._llm.chat_with_tools(...)   # 同步函数
            └─ llm.py:161  self._client.chat.completions.create(...)
                 └─ OpenAI 同步 SDK
                      └─ socket.recv(...)                # 线程停在这里

模型一次响应可能 2~10 秒，最多 5 轮，中间还要跑工具（agent.py:353）。这几十秒里，调用栈上的函数帧都“挂着”，线程没有一刻能腾出来。

三、with 到 async with

普通 with 解决的是“用完必须还”：

with borrow_key() as key:
    use(key)

# 等价于：
cm = borrow_key()
key = cm.__enter__()
try:
    use(key)
finally:
    cm.__exit__(...)

对象只要实现了 __enter__ / __exit__，就能被 with 使用。当“借”和“还”本身需要等待 I/O 时，就换成异步版：

普通版异步版
withasync with
__enter__async def __aenter__
__exit__async def __aexit__
 
async with cm as x:
    body

# 等价于：
x = await cm.__aenter__()
try:
    body
finally:
    await cm.__aexit__(exc_type, exc, tb)

跑一遍，看清理是否一定发生

class Lock:
    async def __aenter__(self):
        print("enter: open the door")
        return "key"

    async def __aexit__(self, exc_type, exc, tb):
        print(f"exit: lock the door (reason={exc_type.__name__ if exc_type else 'normal'})")
        return False

async def main():
    async with Lock() as key:
        print(f"working with {key}")
        raise RuntimeError("fell over")

try:
    asyncio.run(main())
except RuntimeError as e:
    print(f"outside caught: {e}")
enter: open the door
working with key
exit: lock the door (reason=RuntimeError)
outside caught: fell over

即使函数体抛异常，exit 仍会执行；收尾完成后，异常才继续往外抛。__aexit__ 返回 True 会吞掉异常，返回 False 则继续抛。

四、放回 mcp_client.py

async with stdio_client(params) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()
        result = await session.list_tools()
  • stdio_client(params) 是一个异步上下文管理器工厂；真正的动作在 __aenter__：启动子进程、接好 stdin/stdout 管道。
  • as (read, write) 解包它返回的二元组，拿到两个流对象（不是文件路径）。
  • 退出时逆序清理：先关 ClientSession，再关闭管道、结束子进程。
  • return 写在最内层也安全——return 会先触发两层 __aexit__。

五、“让出调用栈”是什么意思

同步函数只有一条出路：return。它不能在中途说“我先歇会儿，你去干别的”。await 才能把当前协程挂起、把控制权还给事件循环，之后从暂停点恢复。

所以 run() 无法让出，不是写法问题，而是它内部没有任何 await 点：整条调用链都是同步 SDK。

六、怎么快速判断

  1. 看定义：def 是同步，async def 是异步。
  2. 看内部：有没有网络、磁盘、time.sleep、subprocess.run。
  3. 看 SDK：OpenAI(...) 是同步客户端，AsyncOpenAI(...) 才是异步。
  4. 经验清单：requests.get、openai.OpenAI、Path.read_text、同步数据库驱动——全是阻塞的。

七、四个常见误解

  • “同步 = 单线程”：不是。10 个线程各跑同步函数互不影响。
  • “异步 = 多线程”：不是。asyncio 是单线程协作式并发，靠 await 主动让出。
  • “阻塞会卡死整个程序”：只卡住那个线程；只有它跑在唯一的事件循环线程上，才等于卡死服务。
  • “asyncio.run 就是异步”：对调用者仍是同步阻塞——它自己建事件循环，跑完协程才返回（mcp_client.py:143）。
