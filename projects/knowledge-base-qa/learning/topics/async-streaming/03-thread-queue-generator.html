专题 · 03

线程 + 队列 + 生成器

一句话：线程负责“同时”，队列负责“交接”，生成器负责“一点点吐给浏览器”。这是把同步 agent 循环接到 HTTP 流式响应上的桥。

一、为什么需要桥

AgentRunner.run() 是推模式：事件发生时调用你给的回调。

while rounds < max_steps:
    result = self._llm.chat_with_tools(...)
    for call in result.tool_calls:
        _emit(on_event, {...})        # 推：调用回调
        step = self._run_tool(...)

StreamingResponse 需要拉模式：反复问“下一块好了吗”。两种模式直接对接不了。

错误写法结果
在回调里 yieldSyntaxError：yield 只能出现在生成器函数自己的函数体里。
先跑完 run() 再逐条 yield功能对，但一点不流式：用户白屏等到全部结束。

二、三个零件

零件解决什么代码
threading.Thread让 run() 和“往外写”同时发生routes.py:282
queue.Queue两个线程之间安全地交接数据routes.py:251
生成器 yield给 StreamingResponse 提供拉模式接口routes.py:284-289

三、时序

t=0.00  路由函数返回 StreamingResponse（worker 已在跑）
        worker:  runner.run(...)
                  └─ _emit(step_start) → queue.put(...)
        generator: queue.get() 立刻拿到 → yield → 浏览器收到第一帧
t=1.20  worker:  _emit(tool_call) → queue.put → generator 立刻 yield
t=3.40  worker:  run() 返回，开始按 8 字发 token（每片 20ms）
t=4.00  worker:  queue.put(done) → queue.put(None)
t=4.00  generator: 读到 None → break → 流关闭

等价的最小实验（worker 每 0.2 秒产生一个事件）实际输出：

route returned at 0.00s
yield {'event': 'step', 'i': 0} at 0.20s
yield {'event': 'step', 'i': 1} at 0.40s
yield {'event': 'step', 'i': 2} at 0.60s
done at 0.60s

route returned at 0.00s 是关键：路由先返回响应头，后面的 0.6 秒才在迭代生成器时逐块写 body。

四、逐行拆 routes.py:242-295

runner = _agent(request)
events: queue.Queue = queue.Queue()

每个请求一个队列，请求之间天然隔离。

def worker() -> None:
    try:
        run = runner.run(..., on_event=events.put)

events.put 是方法对象，直接当回调；agent 每次 _emit 就是往队列塞一条消息。

    except Exception as exc:
        events.put({"event": "error", "message": str(exc)})
        events.put(None)
        return

线程里的异常不会自动传到主线程。不 catch 的话 worker 悄悄死掉，生成器会永远阻塞在 get() 上——浏览器拿不到数据，连接挂到超时。

    for offset in range(0, len(run.answer), 8):
        events.put({"event": "token", "text": run.answer[offset:offset + 8]})
        time.sleep(0.02)

这是模拟逐字输出：把最终答案切成 8 字一片。模型本身仍是一次性返回，真正的原生 token 流需要改 LLM 层。

    events.put({"event": "done", ...})
    events.put(None)

None 是“没有更多了”的哨兵，等价前端的 controller.close()。

threading.Thread(target=worker, daemon=True).start()

创建线程 → 指定函数 → 启动。见下文“线程语法”。

def generator():
    while True:
        item = events.get()        # 队列空则阻塞，不烧 CPU
        if item is None:
            break
        yield f"event: {item['event']}\ndata: {json.dumps(item, ensure_ascii=False)}\n\n"

每个 yield 是一帧 SSE；ensure_ascii=False 让中文直接输出。

return StreamingResponse(generator(), media_type="text/event-stream",
    headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})

X-Accel-Buffering: no 是给 Nginx 看的：别攒着，立刻转发。

六、生成器是什么

普通函数 return 一次就结束；生成器 yield 可以很多次，每次暂停并保留执行位置和局部变量。

def gen():
    print("  A 进入函数体")
    yield 1
    print("  B 从 yield 1 恢复")
    yield 2
    print("  C 函数结束")

print("1 调用 gen()")
g = gen()
print("2 拿到对象:", type(g).__name__, "| iter(g) is g ->", iter(g) is g)
print("3 第一次 next():", next(g))
print("4 第二次 next():", next(g))
try:
    next(g)
except StopIteration:
    print("5 第三次 next() 抛 StopIteration")
print("6 再遍历一次:", list(g))
1 调用 gen()
2 拿到对象: generator | iter(g) is g -> True
  A 进入函数体
3 第一次 next(): 1
  B 从 yield 1 恢复
4 第二次 next(): 2
  C 函数结束
5 第三次 next() 抛 StopIteration
6 再遍历一次: []
  • 调用 gen() 不执行函数体，只创建对象。
  • 每次 next() 跑到下一个 yield 就暂停。
  • 暂停期间状态保留：执行到哪一行、局部变量是什么。
  • 一次性：跑完后 list(g) 是空的。

for item in generator() 等价于反复 next()，捕获 StopIteration 后结束。

为什么流式要用它

# 列表：先算完全部，再返回
return [make_frame(e) for e in events]

# 生成器：算一个、发一个，内存里始终只有一个
return (make_frame(e) for e in events)

StreamingResponse 拿到生成器后就是一个循环：每 yield 一次，写一块到 HTTP 连接。

精确一点 生成器是拉模式：消费者不 next() 它就不往下走。但这里中间垫了无界队列，worker 会一直塞，所以生产端没被消费者限速；真正被约束的只是“字节什么时候写给浏览器”。

七、线程语法

threading.Thread(target=worker, daemon=True).start()
片段含义
Thread(...)创建线程对象，此时还没跑
target=worker线程启动后调用这个函数；不能写 worker()
daemon=True守护线程：主线程退出时不等它
.start()创建 OS 线程并开始执行，立刻返回
 
t = threading.Thread(target=work)
t.start()      # 立刻返回
t.join()       # 想等它结束才用

实测（work 里 sleep 0.3 秒）：

1 创建完 Thread 对象
  worker: 开始
2 start() 立刻返回 (0.00s)
  worker: 结束
3 join() 等到 worker 结束 (0.30s)

GIL 让 Python 线程不能并行跑 CPU 密集代码，但等 I/O 时会释放 GIL；这里全是等网络，属于 I/O 密集，线程有效。

八、失败路径与坑

情况行为 / 要做什么
worker 漏掉 put(None)生成器永远阻塞在 get()，请求挂死。
worker 抛异常必须自己 try/except，发 error 事件并补 None。
流已开始响应头 200 已发出，不能再返回错误 JSON；错误只能作为事件。
客户端断开生成器被回收，但 worker 仍会跑完，没有取消机制。
队列无界事件太多会堆积；生产环境应设 maxsize 或改用异步队列。
路由写成 async def阻塞的 events.get() 会冻住整个事件循环；必须是同步 def（走线程池）。
